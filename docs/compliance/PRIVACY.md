# PRIVACY - CheckLine 隐私与数据边界

本文同时约束开发行为并为未来 App Store 隐私申报提供事实底稿。申报只能依据待提交构建的真实行为，不能把路线图能力写成已经存在。

## 一、核心承诺

预算线不碰用户的钱，只管理用户主动输入的预算数字。

- 不连接银行、支付宝、微信或银行卡。
- 不读取真实账户余额或交易流水。
- 不出售、共享或用于广告投放。
- 不用 AI 自动决定消费归属或结余用途。
- MVP 不接 Analytics、Tracking、广告或第三方崩溃收集 SDK。

## 二、当前构建的真实状态

当前 App 运行迁入的 SwiftUI 历史交互原型：

- 数据来自代码中的虚构 Sample，只保存在运行内存。
- 退出 App 后不承诺保留原型操作结果。
- 没有 SwiftData 正式模型。
- 没有网络请求、自有后端或第三方数据服务。
- 没有启用 iCloud / CloudKit。
- 不请求通知、照片、麦克风或语音识别权限。
- 不收集设备标识符、诊断、使用行为或个人身份信息。

因此当前构建不能对外宣称已经具备本地持久化、跨设备同步、数据导出或云端删除能力。

## 三、第一轮 MVP 数据行为

第一轮 MVP 计划加入本地 SwiftData。实现并验证后，用户主动输入的数据包括：

| 数据 | 示例 | 计划存储位置 |
|---|---|---|
| 预算 | 名称、周期、总额、分类、超支策略 | 用户设备本地 SwiftData |
| 消费 | 金额、分类、备注、时间 | 用户设备本地 SwiftData |
| 预算关联 | 一笔消费归属哪些预算 | 用户设备本地 SwiftData |
| 结算 | 最终支出、结余、用户确认结果 | 用户设备本地 SwiftData |

第一轮 MVP 不包含：

- 心愿数据
- 支付截图或原始语音
- 银行或支付平台数据
- iCloud 同步数据
- 自有服务器数据
- 分析、广告或营销画像

本地持久化完成前，以上内容只代表计划，不是当前构建事实。

## 四、当前数据流

```text
当前历史原型：虚构 Sample -> App 内存 -> 进程结束后释放

第一轮 MVP：用户输入 -> 本地 SwiftData -> App 内查看、修改、删除
```

当前与第一轮 MVP 都没有 App -> 开发者服务器或第三方分析服务的数据通道。

## 五、用户控制

第一轮 MVP 正式实现时必须提供：

- 查看自己的预算、消费和结算记录。
- 修改预算和消费记录。
- 删除单条记录和相关关系。
- 删除全部本地数据的明确入口。
- 卸载 App 后由系统删除 App 本地容器。

CSV 导出、iCloud 停止同步和云端数据删除属于后续能力，不能写入当前验收。

## 六、日志与开发数据

- 禁止 `print`、`NSLog` 或 `OSLog` 输出真实金额、预算名、备注等用户内容。
- 调试日志只记录操作类型、耗时和脱敏错误类别。
- Sample 数据统一使用虚构名称与金额。
- 截图、Issue、Commit 和 PR 不包含真实用户数据。
- `.env`、证书、Provisioning Profile 与服务密钥不得提交。

## 七、后续能力门槛

以下能力进入开发前，必须先更新本文并对照真实实现复核。

### iCloud / CloudKit

需要重新明确：

- 哪些 SwiftData Model 同步。
- 用户如何选择开启或关闭。
- 本地数据迁入 CloudKit 的策略。
- 冲突、退出 Apple ID 和删除云端数据的行为。
- App Store Connect 隐私问卷是否变化。

当前不声称任何数据已上传到用户 iCloud。

### OCR

- 只读取用户主动选择的图片。
- 优先使用系统 Picker 的最小权限方案。
- Vision 端侧处理，原始图片不进入 SwiftData。
- 处理后释放图片和中间识别结果。

### 语音

- 明确系统 Speech 是否会使用网络，不能默认宣称全部离线。
- 原始音频不持久化。
- 用户确认解析结果后才生成 Expense。

### 心愿

第三轮新增 Wish 或结算分配模型时，重新评估数据类别、删除关系和导出范围。

### 商业化

接入 StoreKit 时只处理 Apple 提供的交易状态，不把用户预算或消费数据附加到交易信息。

## 八、App Store 隐私申报基线

按当前无网络、无追踪、无开发者数据采集的构建，可评估为 `Data Not Collected`。

正式提交前必须重新检查：

- App 二进制包含的所有 SDK 与 Privacy Manifest。
- 实际权限 Key、网络请求和系统能力。
- SwiftData 是否仍只在本地。
- 是否加入诊断、分析、订阅、反馈或 iCloud。
- App Store Connect 问卷与待提交构建是否逐项一致。

本文不是一次填写后永久有效的声明。每次数据流或第三方依赖变化都必须重新审查。
