# PRIVACY — CheckLine 隐私与数据处理原则

> 本文同时记录“当前构建真实行为”和“新 V1 必须遵守的目标边界”。App Store 申报只能依据待提交二进制的真实行为，不能把目标方案当作已经实现。

---

## 一、核心承诺

**CheckLine 不碰你的真实资金，只在你选择的范围内处理预算数字。**

- 不持有、转账或冻结用户资金；
- 不模拟登录微信、支付宝、银行或其他金融账号；
- 不偷读其他 App 通知；
- 数据来源必须由用户主动配置，并可跳过、断开；
- 完整账本默认留在用户设备；
- 本地无法完成的 AI 判断，只有经用户允许才发送最少必要信息；
- 不出售用户数据，不用于广告定向，不用财务数据训练第三方模型。

---

## 二、当前构建的真实状态

当前 App 启动新首页与文字 Agent 面板：

- 用户创建的预算卡、消费、心愿名称、可选金额与所选币种，以及兑现记录写入本地 SwiftData（`CheckLineSchemaV1`），默认关闭 CloudKit；添加心愿已移除图标选择，既有符号数据继续保留；
- 用户明确添加到消费的图片附件以去除元数据的可读副本单独保存在设备本地，按消费 ID 关联；每笔最多 5 张，可从详情删除，不进入云端或整本账本保存；
- 没有网络请求、自有后端、已启用的 AI Provider 或第三方数据服务；`CloudLLMProvider` 默认关闭，App 入口未打开；
- 没有启用 iCloud 同步；
- 不请求通知、全库照片或邮箱权限；麦克风与 Speech 权限仅在用户点击语音并确认用途后按需申请；
- 已接入端侧 Speech 转写代码：先检查当前语言是否支持端侧，请求强制端侧识别，不向网络回退；音频仅在内存中处理，不保存、不写日志；
- 没有 Apple Pay、短信、邮件或账单导入连接器；
- 不收集设备标识符、诊断、使用行为或个人身份信息；
- 旧四 Tab 样机不再启动，其内存 Sample 不会写入新账本；
- 显式 Debug 参数 `-design-preview` 使用独立内存账本并标记“示例数据”，不会读写用户账本，Release 不启用。

设备上的用户账本按 Apple 提交时规则判断是否算“收集”。一旦打开云端 AI、来源连接或网络请求，必须重新评估隐私标签。

转写先进入本机任务草稿，用户检查、编辑并点击发送后才进入现有文字理解／确认流程；取消恢复原输入，关闭或进入后台停止采集。云端模型仍关闭。2026-10-04 的接入状态来自代码核查，实际音频识别与真机权限流程尚未运行验证。

2026-10-15 Workflow 修复仅增加服务端响应中的可选原动作提示，不扩大请求允许清单。审阅页的任务、消费、心愿、余额、汇率及附件失败均为虚构数据，只在当前页面内存中模拟，刷新重置；没有新增上传、浏览器持久化、真实附件读取或手机账本读写。App 仅增加候选解码兼容，云端开关仍关闭；演示中的草稿恢复不代表已完成原生多轮接入。

### 2026-10-12 已确认的草稿与附件修复边界

2026-10-13 月度日期设置沿用本机输入草稿：仅新增用户选择的周期类型、开始日和结束日，不保存派生周期结果，不上传；成功创建或明确放弃后随该任务清除。旧草稿继续读取，权限、网络和 iCloud 边界不变。

本轮已增加心愿创建、按心愿隔离的兑现输入草稿，与已有消费/预算草稿同样仅存设备、排除备份；不保存钱包派生结果、真实购买确认或聊天历史。异步照片读取绑定原任务，关闭、后台或更换任务取消未完成读取；相册选择句柄只在当前面板内存保留，重启后未读取成功的图片需要重新选择。已明确添加的图片仍只保存去元数据副本，附件失败续存不会重复创建消费。磁盘草稿重开、任务隔离、旧回调与部分失败有可靠性测试；原生图片放大、语音不可用时保留文字已运行。实际音频转写和真机权限尚未验证，范围见 [交付记录](../design/evidence/2026-10-12-existing-experience/README.md)。

## 三、V1 目标数据分类

### 3.1 用户主动创建的数据

| 数据 | 示例 | 目标默认存储 |
|------|------|--------------|
| 预算卡 | 名称、额度、币种、周期、规则 | 设备本地 SwiftData |
| 消费记录 | 金额、币种、时间、商家、备注、标签 | 设备本地 SwiftData |
| 消费图片附件 | 用户明确添加的图片，保存去除元数据的可读副本 | 设备本地独立文件，按消费 ID 关联，可删除 |
| 结算与调整 | 支出、结余/越线、覆盖快照、追溯修正 | 设备本地 SwiftData |
| 心愿 | 名称、参考金额、链接、完成状态 | 设备本地 SwiftData |
| 钱包账本 | 结余、越线、兑现、退款和调整 | 设备本地 SwiftData |
| 匹配规则 | 用户确认的商家/标签/预算归属规则 | 设备本地 SwiftData |

iCloud 是否进入首发尚未确认。启用前必须另行设计迁移、冲突、关闭同步和云端删除，不在当前文档中默认承诺。

### 3.2 用户选择的数据来源

| 来源 | 可能读取的数据 | 处理原则 |
|------|----------------|----------|
| 文字 Agent | 用户输入的交易或操作描述 | 只为当前行动解析 |
| 语音 | 用户主动录制的语音 | 提取文本后丢弃原始音频 |
| 图片/OCR | 用户选择的小票、截图或商品图 | 提取必要字段后丢弃原图；只有明确保存为消费附件时保留无元数据副本 |
| Apple Pay 自动化 | 系统提供的金额、商家、时间、卡片线索 | 只保留交易和去重必要字段 |
| 银行短信自动化 | 用户配置规则命中的交易短信 | 只提取必要交易字段，不保存无关全文 |
| 邮件账单/小票 | 用户授权规则或主动转发的邮件 | 只处理指定来源，默认不读取完整邮箱 |
| 账单导入 | 用户主动选择的账单文件 | 导入后只保留标准化交易和必要来源证据 |

### 3.3 系统产生的数据

- 归属置信度、待确认和未纳入状态；
- 跨来源去重结果；
- 各来源连接状态、最后覆盖时间和缺口说明；
- 结算预览、钱包余额和待恢复差额；
- Agent 行动风险等级与用户确认记录。

## 四、设备优先处理

目标默认数据流：

```text
用户输入 / 系统自动化 / 文件导入
  ↓
设备端提取与标准化
  ↓
设备端去重、金额计算和本地存储
```

原则：

- 原始账单、完整账本和去重结果默认不进入开发者自有服务器；
- 预算剩余、结算、钱包和待恢复差额由确定性本地逻辑计算；
- 手动/文字记录和本地账本不能依赖网络；
- 邮件中转、云端 AI、地区银行聚合或 iCloud 上线前必须分别更新本文并取得对应授权；
- 任何外部能力失败都要降级到本地核心循环。

## 五、AI 数据最小化

### 5.1 优先顺序

1. 设备端规则和可用端侧能力；
2. 能不发送就不发送；
3. 本地无法判断且确实影响当前任务时，告知用户并获得允许；
4. 只发送当前任务需要的最少字段。

### 5.2 云端 AI 请求字段（允许清单）

启用 `CloudLLMProvider` 时，请求 JSON **只含**下列字段，对应 `LLMRequestPayload`：

| 字段 | 内容 |
|------|------|
| `system` | 固定系统提示（角色、允许的 intent 类型、JSON schema）。不含用户账本。 |
| `userMessage` | 当前这一句用户原文、语音转写或 OCR 文字。 |
| `context.budgetCards[]` | 活跃/待结算预算卡的 `name`、`cycleType`、`currencyCode` |
| `context.recentMerchants` | 最近 ≤10 条去重商家名 |
| `context.tagNames` | 已有标签名 |
| `context.deviceTime.timestamp` | 本次发送时的 ISO 8601 时间戳，用于确定用户说的今天／昨天；不从草稿恢复旧时间。 |
| `context.deviceTime.timeZoneIdentifier` | 当前系统时区，用于日历日期计算；不获取 GPS、位置权限或设备标识。 |

默认不发送、实现上也不得加入：

- 预算额度、已用、剩余、结余、越线；
- 心愿钱包余额、待恢复差额、钱包分录；
- 完整交易记录、消费金额、周期 ID 列表、心愿清单；
- 邮箱或短信全文、原图、原音频；
- 银行卡号、账号、身份信息。

用户自己打在 `userMessage` 里的数字会原样发送；那是当前指令，不是从账本导出的余额。图片「发给模型帮我看」仍是显式 opt-in，V1 默认关闭，不在本 Provider 请求里附带图片。

2026-10-14 Rex 要求取得设备时间，允许清单加入可选 `context.deviceTime`。这两个字段仅交 CheckLine API 的日期程序，转发上游模型前从消息中剥离；不写入任务草稿、账本字段或服务日志。旧客户端缺少该对象仍可用，日期不明确时追问。当前 App 云端仍关闭，本轮只在本地与模拟请求中验证，不代表真实上传已启用。

### 5.3 AI 禁止行为

2026-10-13 Workflow 准备阶段：`services/agent-api/` 仅以虚构样例本地验证，请求复用上方允许清单，不增加设备时间、任务历史或账本 ID 列表。本轮没有把已提供的 DeepSeek 密钥写入文件或调用真实模型，App 云端仍关闭。后续用户确认启用时，请求先到 CheckLine 服务端，再到 DeepSeek；服务端固定系统提示并严格检查字段，不持久化请求正文、候选或思考内容，不将失败正文写入日志。服务凭据仅在服务端配置，联调包和镜像不包含密钥。第三方自身的实际处理地点、保留与训练约定仍需核实，不能用自有服务器不存正文来承诺第三方零留存；公网 TLS、访问认证、当前任务发送同意和公开上线要求尚未完成。

- 自由生成或直接修改余额；
- 绕过确认执行结算、钱包扣减、删除或历史追溯；
- 将用户数据用于模型训练或广告；
- 用户断开来源后继续获取新数据。

## 六、来源连接与权限

- Apple Pay、短信、邮箱和账单导入都可跳过；
- 拒绝权限后，文字 Agent 与本地账本仍能使用；
- 每个来源连接前说明会读取什么、覆盖什么、漏什么和如何断开；
- 邮箱优先使用指定发件人/规则或主动转发，不默认请求整个邮箱；
- 短信由用户创建系统自动化主动转交，App 不扫描全部短信；
- 图片只处理用户明确选择的内容；
- “已连接”不能描述成“所有消费都已同步”。

详细权限和降级见 `../engineering/PERMISSIONS.md`。

---

## 七、数据保留与删除

### 7.1 保留

- 标准化交易、结算、钱包账本和用户确认规则按用户需要保存在本地；
- 原始音频和仅用于 OCR 的原始图片完成提取后立即丢弃；明确保存为消费附件的图片仅保留去除元数据的副本；
- 邮件/短信全文原则上不保存，只保留必要交易字段和来源证据；
- 导入临时文件处理后删除；如技术上需要短期缓存，必须明确期限并加密。

### 7.2 用户权利

正式 V1 必须让用户：

- 查看所有预算、交易、结算、心愿和钱包变化；
- 修改或删除单条记录；
- 断开任一数据来源；
- 撤销低风险 Agent 行动；
- 删除全部本地数据。

结构化导出是否进入 V1 尚未确认；一旦承诺或法规要求，必须覆盖预算、交易、结算、钱包和心愿的可读数据。删除已影响结算或钱包的记录时，必须先展示追溯影响，不能破坏金额一致性。

---

## 八、日志、分析与调试

- 禁止在 `print`、`OSLog`、崩溃日志或测试快照中记录真实金额、商家、邮箱、短信、预算名、备注、心愿名称和用户输入全文；
- 日志只使用脱敏事件码、匿名本地 ID 和耗时；
- V1 不默认接入广告、Tracking、Analytics 或第三方崩溃收集 SDK；
- 如接入诊断或产品分析，先说明字段、保留期和退出方式，并更新 App Store 隐私标签；
- Sample/Mock 数据必须为虚构内容。

---

## 九、明确禁止的数据路径

- 读取其他 App 通知中心内容；
- 模拟登录微信、支付宝或银行；
- 抓取支付 App 界面或绕过平台权限；
- 在用户不知情时扫描完整邮箱或短信；
- 将完整账本上传到通用 AI 服务；
- 将心愿钱包描述为真实资金账户；
- 将金融数据用于广告、出售或第三方模型训练。

## 十、第三方与地区连接器

每接入一个第三方或地区连接器，必须先记录：

- 服务商、能力和地区；
- 获取的数据字段；
- 数据是否经过服务商/开发者服务器；
- 数据保留期与删除方式；
- 用户授权、撤回和断开方式；
- 子处理方与跨境传输；
- 失败时的降级路径；
- App Store 与当地法规要求。

FinanceKit、Open Banking 聚合商、邮箱中转和 AI Provider 都必须逐项审查，不能因为在路线图中出现就自动批准。

---

## 十一、App Store 隐私申报

- **当前构建**：无已启用网络；麦克风与 Speech 权限只在用户触发时申请，音频仅作端侧转写、不保存。账本与文字草稿留在设备，`CloudLLMProvider` 未打开。是否仍填 `Data Not Collected` 按提交时 Apple 对“仅存设备”的规则判断。
- **正式 V1**：必须重新检查用户内容、财务信息、标识符、诊断数据、是否与身份关联和是否用于追踪。
- 只存在用户设备的数据是否属于“收集”，按 Apple 提交时最新规则判断。
- 一旦加入云端 AI、邮件中转、银行聚合、iCloud、反馈或诊断，必须重新填写。

---

## 十二、上线前隐私验收

- [ ] 当前文案和实际网络/权限行为一致；
- [ ] 所有来源都可跳过和断开；
- [ ] 原图、原音频和导入临时文件按策略删除；
- [ ] 云端 AI 请求字段已最小化；
- [ ] 日志扫描不含真实财务信息；
- [ ] 已确认范围内的删除路径可用；如包含导出，则导出范围完整；
- [ ] 第三方服务和数据保留已登记；
- [ ] App Store 隐私标签与待提交二进制一致；
- [ ] 隐私政策、产品文案和代码行为一致。

## 2026-10-01 未完成任务草稿

未完成创建 / 记录任务及月度额度编辑的输入与上下文保存在设备本地，关闭和重启后恢复；成功完成或用户明确放弃时清除。明确添加的图片保留去元数据副本，每任务最多 5 张；成功后迁入消费附件，不另保留草稿副本。草稿及附件排除系统备份，不上传。完整对话不持久化；仅用于识别的原图 / 音频、邮件短信无关全文仍不保留。隔离演示不用正式草稿目录。网络、iCloud 和系统来源接入范围未改变。
