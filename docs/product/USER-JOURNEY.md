# USER-JOURNEY — CheckLine 当前版本 Day 1-30 用户旅程

> 这份文档定义当前版本的新用户从下载到稳定使用的 30 天典型旅程。
> 当前版本聚焦「预算钱包闭环」：建预算、记一笔、看预算详情、看统计、完成结算、回看结果。
> 长期情感激励功能后置，不进入本轮旅程和验收。
>
> 配套阅读：`../../PRODUCT.md`、`PRD.md`、`FEATURE-LOOP.md`、`ROADMAP.md`。

---

## 一、当前版本范围

### 1.1 本轮旅程要覆盖

- 首页预算钱包横滑卡片
- 预算列表和预算详情
- 新建预算
- 记一笔弹窗
- 统计概览和消费日历
- 我的 / 设置
- 结算清单
- 结算完成反馈

### 1.2 本轮旅程不覆盖

- 长期激励目标管理
- 结余分配闭环
- 达成庆祝动画
- 真实账户、银行卡、资产管理口径
- 自动识别消费意图的智能建议

## 二、典型用户画像

### 主角：小满

- 28 岁，互联网产品运营，月薪 ¥18K
- 每月日常开销约 ¥4,500
- 用过 1-2 个记账 App，坚持不到 7 天
- 不想做复杂财务管理，只想知道「这段时间还能花多少」
- iPhone 15 + MacBook Air，重度 Apple 生态用户

### 她现在的核心问题

> 「我每个月不是完全没预算，但总是到月底才发现花多了。我想把一段时间、一件事、一笔预算放在一起看，随时知道还剩多少。」

## 四、阶段详细旅程

### 阶段 1 · Day 0：发现与下载

| 维度 | 内容 |
|------|------|
| 触点 | App Store / 朋友推荐 / 社交内容 |
| 用户行动 | 看到「预算线 / CheckLine」，下载 |
| 想法 | 「这个看起来像预算工具，不像传统记账本」 |
| 情绪 | 半信半疑 |
| 痛点 | 不知道它和普通记账 App 有什么区别 |
| 机会 | 截图前 3 张必须讲清：预算钱包、记一笔、结算回看 |

关键产出：

- App Store 第 1 屏：预算钱包横滑卡片
- App Store 第 2 屏：记一笔后的预算变化
- App Store 第 3 屏：结算清单和结算完成反馈

### 阶段 2 · Day 1：首次启动和建第一个预算

| 维度 | 内容 |
|------|------|
| 触点 | 首次启动 → 引导建预算 → 主屏 |
| 用户行动 | 选择「月度生活」模板，设 ¥5,000，确认分类，进入首页 |
| 想法 | 「这个月生活预算就是 ¥5,000，我先试试看」 |
| 情绪 | 期待 |
| 痛点 | 模板太复杂会让用户放弃；解释太长会让用户跳过 |
| 机会 | 引导只讲一句：一段时间、一件事、一笔预算 |

Aha 时刻 #1：

用户第一次看到首页预算钱包，理解「预算不是账户，是这段时间这件事还能花多少」。

### 阶段 3 · Day 1 晚上：第一笔记录

| 维度 | 内容 |
|------|------|
| 触点 | 首页右下角 + → 记一笔弹窗 → 首页预算变化 |
| 用户行动 | 晚饭外卖 ¥38，输入金额，默认归到「7 月生活」，选择「伙食」，记下 |
| 想法 | 「数字变了，进度条也变了」 |
| 情绪 | 满足 |
| 痛点 | 找不到入口或弹窗慢，会破坏“轻”的预期 |
| 机会 | + 号固定在右下角，弹窗响应控制在 200ms 内 |

Aha 时刻 #2：

用户看到剩余额和进度条实时变化，确认这不是填表工具，而是一个能反馈预算状态的工具。

### 阶段 4 · Day 2-3：继续记录和修正

| 维度 | 内容 |
|------|------|
| 触点 | 首页、预算详情、记一笔弹窗 |
| 用户行动 | 每天记录 1-2 笔，偶尔进入详情看分类剩余 |
| 想法 | 「分类能看出伙食和交通花了多少」 |
| 情绪 | 平稳 |
| 痛点 | 分类不符合生活习惯时需要能改；误记后要能看见记录 |
| 机会 | 详情页把分类、最近记录和剩余金额放在同一屏 |

### 阶段 5 · Day 4-7：第一周回看

| 维度 | 内容 |
|------|------|
| 触点 | 统计 Tab、消费日历 |
| 用户行动 | 第 7 天打开统计，看本月结余和分类分布，再进日历看哪天花得多 |
| 想法 | 「我这周主要花在伙食和交通」 |
| 情绪 | 对消费节奏有数 |
| 痛点 | 统计如果像财报会太重；日历如果没有记录联动会没有意义 |
| 机会 | 统计页只做预算回看，不做复杂资产分析 |

Moment of Truth #1：

第一周用户必须知道自己是否愿意继续记录。如果统计和日历不能把记录变成反馈，用户会回到旧习惯。

### 阶段 6 · Day 8-15：多预算激活

| 维度 | 内容 |
|------|------|
| 触点 | 预算列表 → 新建预算 → 首页钱包横滑 |
| 用户行动 | 新建一个「周末出行」或「学习」预算，开始同时跑多个预算 |
| 想法 | 「不同生活场景可以分开看」 |
| 情绪 | 进入稳定使用 |
| 痛点 | 多预算如果像多个账户，会让用户理解偏掉 |
| 机会 | 文案始终说预算和钱包，不说真实账户或资产 |

Moment of Truth #2：

用户能否顺利从单预算走到多预算，是当前版本价值扩大的关键。

### 阶段 7 · Day 16-22：中段回看和调整

| 维度 | 内容 |
|------|------|
| 触点 | 首页、预算详情、统计 |
| 用户行动 | 发现某个预算用得快，进入详情查看分类，后续消费更谨慎 |
| 想法 | 「这段预算快用完了，我得注意」 |
| 情绪 | 有边界感 |
| 痛点 | 不能制造焦虑，不能用惩罚式文案 |
| 机会 | 用「今日预算用完了」「预算快用完了」这类温和提示 |

### 阶段 8 · Day 23-28：结算预期出现

| 维度 | 内容 |
|------|------|
| 触点 | 预算列表、预算详情 |
| 用户行动 | 看到到期预算进入待结算状态，点进详情预览结算 |
| 想法 | 「这个月快结束了，看看最后剩多少」 |
| 情绪 | 期待结果 |
| 痛点 | 结算如果只是一行数字，用户不会有完成感 |
| 机会 | 结算清单需要清楚展示总支出、预算总额、结余和关联账确认 |

### 阶段 9 · Day 28-30：月度结算

| 维度 | 内容 |
|------|------|
| 触点 | 预算列表 → 待结算预算 → 结算清单 → 结算完成反馈 |
| 用户行动 | 打开待结算预算，确认关联账，点「完成结算」，回到首页或统计 |
| 想法 | 「这段预算结束了，我知道剩了多少」 |
| 情绪 | 有完成感 |
| 痛点 | 关联账归属不能替用户拍板 |
| 机会 | 当前版本只展示结算结果和归档反馈，不做额外分配流程 |

Aha 时刻 #3：

用户完成一次预算周期，从「建预算」走到「结算完成」，形成当前版本的完整闭环。

## 六、按时间轴的产品介入策略

### 6.1 通知节奏

| Day | 触点 | 通知文案方向 |
|-----|------|--------------|
| Day 1 完成引导后 | 申请通知权限 | 说明只提醒预算节奏和结算 |
| Day 4 | 3 天没记录 | 温柔召回，不责备 |
| Day 7 | 第一周回看 | 提醒查看统计 |
| Day 14 | 预算过半 | 提醒预算节奏 |
| Day 21 | 预算快用完 | 提醒边界临近 |
| Day 28 | 快到结算日 | 提醒提前看看 |
| Day 30 | 可以结算 | 引导进入结算清单 |

### 6.2 教育节奏

| Day | 触发条件 | 提示方向 |
|-----|---------|----------|
| Day 1 第一笔完成 | 回到首页 | 看看预算钱包剩余变化 |
| Day 3 第一次进详情 | 预算详情页 | 分类可以帮你看见钱花在哪里 |
| Day 7 第一次进统计 | 统计页 | 这里用来回看预算节奏 |
| Day 15 新建第二个预算 | 新建完成 | 不同生活场景可以分开管理 |
| Day 30 完成结算 | 结算完成页 | 这段预算已经归档，可以去统计回看 |

## 七、流失风险窗口

| 窗口 | 风险 | 流失原因 | 干预策略 |
|------|------|----------|----------|
| Day 1 引导 | 高 | 没讲清预算钱包是什么 | 引导只保留最短心智 |
| Day 1 第一笔 | 高 | 入口难找或反馈弱 | + 号固定，记录后有明确反馈 |
| Day 4-7 | 高 | 记录没有变成回看价值 | 统计和日历必须能看出变化 |
| Day 8-15 | 中 | 多预算理解成真实账户 | 文案和视觉坚持预算容器 |
| Day 28-30 | 高 | 结算没有完成感 | 结算清单和完成反馈要清楚 |

---

## 八、30 天后用户应该能说什么

理想画像：

> 「我现在知道每段预算还剩多少。每天记一两笔不会太累，周末能看统计和日历。月底结算的时候，我能知道这段预算最后剩了多少，也能把旧预算归档。」

如果用户在 Day 30 做不到上面这些，回头看是哪个阶段的体验没接住。
