# PRD - 预算线 CheckLine 当前版本产品需求

> 本 PRD 是当前版本的产品需求主文档。
> 当前版本先做预算钱包、记一笔、统计回看、我的/设置和基础结算。
> 心愿功能保留为后续版本，不进入当前产品主线或 MVP 验收。

---

## 一、产品定位

**预算线 CheckLine** 是一个帮助用户划定、看见和回看消费边界的预算 App。当前界面可以使用「预算钱包」或预算卡片表达独立预算，但不把它们表现成真实资金账户。

用户每天最需要知道：

- 当前预算还能花多少
- 今天花的钱归到哪个预算
- 哪些分类快到线了
- 这个月或这次活动最终剩了多少

产品心智是「线」：给自己划一条消费边界，随时检查自己离这条线还有多远。

浅色卡片、钱包横滑、分组列表和简洁统计是当前体验样机的可用基线，不是产品需求或永久品牌规则。外部项目只作为历史参考；具体设计以 `docs/design/DESIGN.md` 中已经确认的 CheckLine 方案为准。

## 二、当前版本原则

1. **品牌叫预算线，核心是用户主动划定的消费边界。**
   「预算钱包」是当前可用的 UI 表达，不是真实账户，也不限定以后必须使用某种卡片或钱包形式。

2. **每个预算都是独立容器。**
   每个预算有自己的周期、总额、分类、记录和结算；多个预算平等并存，当前上下文必须清楚。

3. **钱的决定权归用户。**
   系统可以计算、预填、提醒和提供建议，但凡会改变金额含义、消费归属或最终结果，都不能在用户不知情的情况下替用户决定。

4. **心愿后置。**
   心愿是长期情感闭环，但当前版本不做心愿 Tab、心愿详情、心愿达成动画和结算转心愿。

5. **统计和日历服务预算回看。**
   统计页回答「钱花在哪里、哪条线快到了、哪天花了什么」，不做复杂财务报表。

6. **"扣血"仅限内部沟通。**
   用户界面不出现「扣血」。核心术语保持预算线、多预算、记一笔、已用、还能花和结余；具体微文案可以在不改变产品含义的前提下迭代。

7. **无障碍是底线。**
   核心流程在文字缩放、VoiceOver、减少动态效果等场景下仍然可理解、可操作。44pt 和对比度数值是检查参考，不限定控件外观或品牌配色。

## 三、信息架构

### 3.1 核心任务与当前导航方案

当前版本必须让用户清楚到达首页状态、预算管理、统计回看、我的/设置和记一笔。体验样机当前使用四个主入口：

| Tab | 作用 |
|-----|------|
| 首页 | 当前预算钱包总览、横滑切换、快速记一笔 |
| 预算 | 所有预算钱包列表、预算详情、新建/编辑预算 |
| 统计 | 月度概览、预算 vs 实际、分类分析、消费记录日历 |
| 我的 | 个人状态、预算设置、通知、外观、关于 |

体验样机中「记一笔」不占 Tab，使用首页和关键页面的主操作入口。

四 Tab 和浮动入口属于当前设计方案，不是永久产品规则。后续导航可以经设计确认调整，但不能降低核心任务的可发现性；心愿不进入当前版本导航。

### 3.2 后续平台

当前没有 macOS Target，也不提前固定侧栏、内容宽度、弹窗或快捷入口。进入第四轮后，在保持产品心智、数据关系和用户决定权一致的前提下，按 macOS 的输入方式和使用场景重新设计。

## 四、核心模块需求

### 4.1 首页

首页首先回答“我当前在看哪条预算线、这段时间已经用了多少、还能花多少、最近发生了什么”。

必须包含：

- 明确的当前预算上下文和切换其他预算的能力。
- 当前预算名称、周期、已用、还能花以及必要的分类或记录摘要。
- 预算状态变化与相关明细之间清楚、连续的关系。
- 一个容易发现的「记一笔」入口。

体验样机当前使用钱包横滑、主卡和联动列表表达这些关系；具体卡片、导航、按钮位置和切换形式由 `DESIGN.md` 管理。

### 4.2 预算

预算模块是所有预算钱包的管理区。

必须包含：

- 预算钱包列表
- 预算详情
- 新建预算钱包
- 编辑预算钱包
- 分类预算与记录列表
- 到期结算入口

预算详情重点回答：

- 这条预算边界是什么
- 目前还能花多少
- 哪些分类用得最多
- 最近记录是什么
- 是否需要结算

删除预算时：

- 首次确认明确告知预算、分类、结算和该预算下的记录关系将被删除。
- 只属于当前预算的消费记录随预算一起删除。
- 如果存在共享消费，再显示一次共享记录确认；逐笔列出记录与仍关联的预算。
- 共享记录默认只移除当前预算归属；用户主动勾选后，才从所有预算和消费历史中删除。
- 第二次确认默认不勾选任何共享记录，并提供“全选”批量操作。

### 4.3 记一笔

记一笔是日常最高频流程。当前版本先做 App 内手动入口。

| 入口 | 场景 | 当前版本 |
|------|------|----------|
| App 内手动 | 主动打开 App 记录 | MVP |
| Widget 速记 | 锁屏一键进入 | 后续 |
| 截图识别 | 截到支付成功页 | 后续 |
| 语音录入 | 长按按钮说话 | 后续 |
| Shortcuts 自动化 | 收到支付通知自动弹 | 后续 |

通用流程：

1. 输入金额
2. 选择归到哪些预算
3. 选择分类
4. 添加备注（可选）
5. 点击「记下这笔」

交互要求：

- 默认选中当前预算钱包。
- 多预算选择是平等标签，不做主副层级。
- 记录成功后，当前钱包金额和进度平滑更新。
- 如果金额超过当前剩余，温柔提示「这个预算快用完了」，不阻断用户。

#### 4.3.1 消费记录管理与删除

消费记录从预算详情进入管理，用户可以单独或批量选择当前预算下的记录。

- 只属于当前预算的记录，删除后同时删除该笔消费实体。
- 同时属于两个或以上预算的记录，删除时必须明确展示仍与其关联的其他预算。
- 默认只从当前预算移除共享记录，不影响它在其他预算中的归属。
- 用户可以逐笔勾选“从所有预算删除”；存在多笔共享记录时提供“全选”，默认全部不勾选。
- 单独删除普通记录后提供约 5 秒撤销；批量删除经过确认后直接生效。
- 当前版本不提供回收站，确认删除预算及批量删除后的数据无法恢复。

### 4.4 统计

统计模块进入当前版本主线。

必须包含：

- 月度概览：本月已用、预算剩余、结余趋势。
- 预算 vs 实际：清楚比较计划金额与实际记录，具体图表形式由设计方案决定。
- 分类分析：哪些分类占比高，哪些预算接近边界。
- 消费记录日历：作为统计模块内的核心视图。
- 预算筛选：按全部预算或单个预算钱包查看。

统计不是商业财务分析，不做复杂报表。它只帮助用户理解：钱花在哪里、哪条线快到了、哪天花了什么。

### 4.5 消费记录日历

日历不单独占 Tab，放在统计模块内。

第一定位：**消费记录日历**。

必须包含：

- 月视图
- 每天是否有记录的视觉标记
- 选中日期后展示当天记录
- 记录显示所属预算钱包标签
- 可切换「全部预算 / 当前预算」

不作为第一版核心：预算周期排期日历、复杂提醒排程。

### 4.6 我的 / 设置

必须包含：

- 个人概览：当前预算摘要和与使用连续性有关的中性信息，不把结余或少花定义成成绩。
- 财务管理：预算设置、记录管理、导出（后续）。
- 通用设置：通知、外观、货币、iCloud 同步（后续）。
- 关于：版本、隐私、反馈入口。

设置页保持清晰、安静，不做过度营销。

### 4.7 结算

结算是预算周期结束时的阶段回看。

当前版本必须包含：

- 结算清单
- 关联账确认
- 总支出
- 结余金额
- 结算完成反馈

当前版本不做「转到心愿」和心愿分配。结余只作为结算结果展示。

### 4.8 超支处理

用户在创建预算时选择超支策略，决定超出预算总额后的行为：

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| `warnOnly`（仅提醒） | 弹温柔提示「今日预算已用完」，不阻断记账 | 日常灵活预算 |
| `strictReview`（严格复盘） | 结算清单中高亮超出金额，提醒用户确认 | 严格预算场景 |

交互要求：

- 超支提示如实表达结果，不使用惩罚性反馈或制造焦虑；具体颜色由设计方案决定。
- 创建预算时引导用户选择，默认 `warnOnly`。
- 不把超支金额自动扣到任何心愿或其他预算。

### 4.9 Widget

Widget 不进当前版本实现。当前版本的 UI 文档可以预留入口，但不把 Widget 作为 MVP 验收项。

后续优先做：

- 当前主预算钱包名称
- 剩余金额
- 进度条
- 点击进入首页或记一笔

### 4.10 教程

教程帮助用户理解 CheckLine 的预算钱包心智。

当前版本教程主题：

| # | 主题 | 说明 |
|---|------|------|
| 1 | 什么是预算线 | 给自己划一条消费边界，线内自由，线外克制 |
| 2 | 多预算怎么用 | 同时管理「月度生活」「京都旅行」「Q3 学习」多个预算钱包 |
| 3 | 一笔消费归多个预算 | 同一笔消费可以同时记在多个预算里 |
| 4 | 什么是结算 | 每次预算结束都能回看总支出、结余和最终归属 |
| 5 | 在哪里记一笔 | 当前先用 App 内手动入口，后续扩展 Widget / 截图 / 语音 |

触发时机：

- 首次创建预算后展示。
- 设置页提供「教程」入口。
- 空状态页面嵌入对应教程入口。

## 五、通知策略

当前版本先做文档设计，不强制进入 MVP 实现。

| 场景 | 触发条件 | 通知文案（示例） | 频率控制 |
|------|---------|-----------------|---------|
| 预算快用完 | 剩余 ≤ 30% | 「6 月生活还能花 ¥1,500」 | 剩余每降 10% 提醒一次 |
| 多日未记 | 连续 3 天无记录 | 「有 3 天没记了，今天花了什么？」 | 每 3 天最多一次 |
| 结算日到 | 重复型到期 / 单次型到期前 1 天 | 「6 月生活可以结算了」 | 到期当天 + 前一天 |
| 新周期开始 | 重复型自动开下周期 | 「7 月生活已开启，总额 ¥5,000」 | 新周期当天 |

文案调性温柔不焦虑，不出现「超支」「扣血」「警告」。

## 六、当前体验样机范围

当前版本原型从历史 14 页收敛为 8 个核心页面：

1. 首页
2. 预算列表
3. 预算详情
4. 新建 / 编辑预算钱包
5. 记一笔弹窗
6. 统计概览
7. 消费记录日历
8. 我的 / 设置

可选补充：

- 结算清单
- 结算完成反馈
- 教程卡片
- 空状态页面（无预算、无记录、无统计数据）

不进入当前原型主线：

- 心愿列表
- 心愿详情
- 心愿达成反馈
- 结算转心愿分配
- 回收站与删除恢复机制；进入该阶段后再定义保留期限、恢复关系与自动清理规则

## 七、验收标准

- 所有相关文档口径一致：当前版本不做心愿 Tab、心愿详情、心愿达成、转到心愿。
- 当前设计方案与 `DESIGN.md` 一致，外部参考不作为验收标准。
- 用户可见文案不出现「扣血」。
- 核心任务入口清楚，「记一笔」容易发现且不与次要操作争夺层级。
- 统计、消费日历、设置被覆盖。
- 预算删除、单条记录删除与批量记录删除遵守共享消费的安全删除规则。
- 本轮不新增正式数据模型字段，不改金额计算规则。
- 关键页面在 VoiceOver、文字缩放、不同屏幕尺寸与减少动态效果场景下仍可理解、可操作；点击可靠性通过真机验证。
