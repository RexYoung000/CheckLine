# PRD — 预算线 CheckLine V1

> 当前版本产品需求主文档。
> V1 要验证的是：用户是否愿意持续依赖自己划出的消费边界，并通过结算把真实结果转化为心愿动力。

---

## 一、产品目标

CheckLine 帮助用户完成四件事：

1. 自己定义一条清楚的消费边界；
2. 用尽可能轻的方式持续获得消费记录；
3. 随时知道每张预算卡已用、剩余和数据可信度；
4. 在周期结束时主动结算，把结余或越线后果带入唯一心愿钱包。

产品不是完整个人财务助手，不判断收入、债务或整体财务健康，也不持有真实资金。

---

## 二、V1 范围

### 2.1 必须完成

- 循环型和一次性预算卡；
- 预算卡创建、编辑、状态查看和周期衔接；
- 预算循环行动 Agent，支持文字、语音和图片；
- Apple Pay、银行短信、邮件三类可选被动来源；
- 通用近期账单导入；
- 交易标准化、跨来源去重、归属确认和纠正规则学习；
- 首页预算状态、处理区和常驻 Agent；
- 主动检查式结算；
- 唯一心愿钱包、心愿清单、越线扣减和待恢复差额；
- 心愿按实际购买确认兑现；
- 迟到交易和退款追溯修正；
- 多币种和数据覆盖提示；
- 设备优先的数据处理与高风险操作确认。

### 2.2 明确不做

- 财务健康总分、收入/债务画像、整套财务规划；
- 投资、借贷、保险、税务建议或交易；
- 一笔消费同时结算多张预算卡；
- 多个心愿钱包和逐心愿资金分配；
- 心愿资金冻结、预留和预约扣款；
- 偷读其他 App 通知、模拟登录支付或银行账号；
- 宣称全渠道、全球银行“安装后自动同步”；
- AI 根据消费数据主动推荐用户买什么。

---

## 三、用户与核心场景

### 3.1 目标用户

- 想控制某类支出或一次具体活动，但不愿维护复杂账本；
- 经常在不同支付渠道消费，账单分散；
- 用过记账工具，但因为记录成本高或缺少行动反馈而放弃；
- 希望知道“这张预算还能花多少”，并为真实结余建立正向用途。

### 3.2 核心场景

| 场景 | 用户需要的答案 |
|------|----------------|
| 创建预算卡 | 我想管理什么、能花多少、持续多久？ |
| 日常打开首页 | 哪张卡需要注意，现在还剩多少，数据完整吗？ |
| 快速记录 | 我刚花的钱能不能一句话或一张图记下？ |
| 被动记录 | 哪些来源已连接、覆盖到什么时候、有没有漏？ |
| 周期到期 | 这些记录足够让我结算吗？结余或越线会怎样？ |
| 心愿兑现 | 我是否已经真实购买，实际花了多少？ |
| 迟到交易/退款 | 它原本属于哪里，会怎样修正历史结果？ |

## 四、信息架构边界

已确认的产品区域：

- **首次引导**：创建预算卡、可选心愿、可选数据来源、可选近期账单；
- **首页**：顶部处理区、固定顺序预算卡、常驻 Agent；
- **记录与待确认**：交易历史、未纳入预算、待确认、来源证据；
- **预算卡**：列表、详情、创建/编辑、周期和归属规则；
- **结算**：数据检查、金额确认、结果；
- **心愿**：唯一钱包、待恢复差额、心愿清单、兑现历史；
- **设置/数据来源**：连接状态、覆盖时间、权限、导入入口；
- **创建 Sheet**：从首页卡片 `+` 或页首功能菜单唤起；Agent 从独立头像进入，复杂任务按确认门禁升级全屏。

2026-09-22 导航与视觉按用户最新确认：TabView 承载首页 / 预算 / 心愿 / 分析，底部左侧原生玻璃图标导航、右侧独立 Agent 头像，个人设置在顶部头像入口。首页不写「首页」，恢复卡夹前沿，右上铃铛看已有待处理事项，功能菜单含记一笔和预算入口；卡片左下角也可直接记一笔。金额展示和交互以 DESIGN 3.1 为准。

## 五、功能需求

### 5.1 首次使用

流程：

1. Agent 询问“你想管理哪部分支出？”；
2. 用户用文字、语音或图片表达；
3. Agent 整理预算名称、额度、币种、周期和必要规则；
4. 用户确认创建第一张预算卡；
5. 可选添加第一个心愿；
6. 可选配置 Apple Pay、短信、邮箱；
7. 可选导入近期账单；
8. 进入首页。

要求：

- 心愿和所有数据来源都可跳过；
- 用户之后能在设置或心愿区域补充；
- 当前周期内的近期记录可计入预算；更早记录只用于识别，不得扣减当前周期；
- 预算卡和心愿必须使用两个不同问题创建，避免概念混淆。

### 5.2 预算卡

必填或必要信息：

- 名称/用途；
- 预算额度；
- 基准币；
- 循环型或一次性；
- 循环规则，或可选截止日期；
- 必要归属规则。

循环型：

- 到期后进入待结算；
- 用户结算前不正式开启下一周期；
- 到期后的新消费进入下周期队列；
- 完成结算后开启新周期并归入队列记录。

一次性：

- 截止日期可有可无；
- 有日期时支持到期结算、提前结算和延期；
- 无日期时由用户主动结束；
- 只有有日期时才计算基于时间的消费速度风险。

### 5.3 交易归属

- 一笔消费最多影响一张结算预算卡；
- 可带多个语义标签；
- 没有合理归属时进入“未纳入预算”；
- 首页或记录页显示已纳入与未纳入预算的金额/记录覆盖，让用户知道预算状态覆盖了多少已知消费；
- 低置信归属可暂计最可能预算卡，但必须拆出待确认金额；
- 待确认金额不能触发确定越线结论；
- 用户能随时修改交易、预算归属和标签。

### 5.4 Agent

支持任务：

- 记一笔或批量识别图片中的多笔记录；
- 修改、删除或补充最近记录；
- 创建、调整或查询预算卡；
- 查询剩余、待确认和来源覆盖；
- 发起结算、处理追溯修正；
- 整理心愿和确认兑现。

输入：文字、语音、图片；心愿创建可补充商品链接。

执行门禁：

- 明确低风险单笔记录直接写入并提供撤销；
- 不确定信息先确认；
- 调额度、改周期、删除、批量修改必须确认；
- 结算、钱包变化、历史追溯必须展示影响并明确确认。

Agent 不负责金额自由计算。预算剩余、结余、钱包余额和待恢复差额必须由确定性规则产生。

### 5.5 数据来源

V1 入口：

| 来源 | 连接方式 | 体验边界 |
|------|----------|----------|
| Apple Pay | 用户首次配置系统交易自动化 | 可较及时，但不代表所有支付渠道 |
| 银行短信 | 用户配置系统自动化转交匹配短信 | 依赖银行模板和短信信息完整度 |
| 邮件账单/小票 | 用户授权指定邮箱规则或转发 | 更适合补全，不保证每笔实时 |
| 近期账单导入 | 用户分享/导入文件 | 通用兜底，系统负责增量和去重 |

要求：

- 首次配置可全部跳过；
- 设置页随时补连或断开；
- 显示连接状态、最后覆盖时间和可能缺失范围；
- 不反复强迫用户连接；
- 各来源先标准化，再跨来源去重；
- 高置信重复自动合并并保留来源证据；不确定时由用户确认。

### 5.6 多币种

- 每张预算卡有基准币；
- 保留交易原币金额；
- 优先使用银行实际入账金额；
- 未入账时使用明确标记来源和时间的暂估汇率；
- 最终入账差异更新同一笔记录，不新增重复消费。

唯一心愿钱包只有一种基准币，规则见 `PRODUCT.md` 第 6.5 节：

- 默认等于第一张预算卡的基准币；已有钱包分录后 V1 不再更改；
- 只在用户确认结算、兑现、退款或追溯调整时换算；
- 同币种汇率为 1；否则优先实际入账汇率，其次为确认页上可见的暂估汇率；
- 没有可展示汇率时，不能完成这次跨币种钱包写入。

### 5.7 首页

必须包含：

- 顶部处理区：待确认、未纳入、数据缺口、边界风险；
- 预算卡主体：已用、剩余、周期状态、待确认金额；
- 用户熟悉的固定卡片顺序；
- 底部常驻 Agent 入口，支持文字、语音、图片；
- Agent 底部任务面板。

交互要求：

- 首页不是聊天窗口，预算状态是第一视觉任务；
- 风险不通过自动重排预算卡制造位置跳动；
- 简单 Agent 操作不离开首页；
- 复杂或高风险动作可展开全屏确认。

### 5.8 边界提醒

- 综合额度消耗、周期进度和近期趋势；
- 解释提醒依据，例如“按最近速度，预计会提前几天用完”；
- 待确认数据只触发可能风险；
- 无截止日期预算不做时间速度判断；
- 提醒温和，不羞辱用户，但不能隐藏真实越线后果。

### 5.9 结算

结算页展示：

- 周期与预算额度；
- 已确认支出；
- 待确认交易；
- 各来源最后覆盖时间；
- 可能缺失的数据；
- 预估结余或越线金额；
- 结算后对心愿钱包和待恢复差额的影响。

流程：

1. 用户处理关键待确认项，或明确接受当前数据；
2. 系统展示最终金额影响；
3. 用户确认完成结算；
4. 生成可追溯结算记录；
5. 循环卡进入下一周期，一次性卡归档。

### 5.10 心愿钱包与待恢复差额

规则：

- 全局只有一个心愿钱包；
- 所有预算结余先补待恢复差额，余下进入钱包；
- 越线金额先扣钱包；钱包不足时归零，未扣部分成为全局待恢复差额；
- 待恢复差额不是第二个钱包；
- 钱包不代表真实存款或完整财务安全额度。

示例：

```text
钱包 500，本期越线 200 → 钱包 300
钱包 100，本期越线 200 → 钱包 0，待恢复差额 100
下期结余 250 → 先补 100，钱包增加 150
```

### 5.11 心愿

- 心愿清单项目包含名称、可选参考金额和统一预设符号；不要求上传图片；
- 不为各心愿预先分配钱包余额；
- 用户表达心愿，Agent 只整理，不主动推荐购买；
- 钱包余额足够时，用户可以自由选择兑现哪个心愿；
- 不提前冻结资金；
- 确认真实购买后按实际成交金额扣钱包；
- 心愿购买不再进入普通预算卡；
- 兑现后保留完成页，展示心愿符号、实际花费与钱包剩余，用户主动返回；
- 余额不足不能标记完整兑现。

### 5.12 迟到交易与退款

- 系统根据发生时间和关联证据定位原周期；
- 先重算并展示对原结算、钱包和待恢复差额的影响；
- 用户确认后生成追溯调整；
- 普通消费退款恢复原周期结果；
- 心愿退款退回钱包，并恢复或确认心愿状态；
- 不允许静默塞入当前周期。

## 六、隐私与信任要求

- 原始账单、完整账本和去重结果默认保留在设备；
- 本地无法判断时，只有用户允许后，才发送最少必要信息给云端 AI；
- 不读取其他 App 通知，不模拟登录金融或支付账号；
- 每个来源使用前说明权限、覆盖和限制；
- 用户可查看、修改、删除和断开数据；
- 高影响金额动作必须可解释、可确认、可追溯。

---

## 七、V1 验收标准

### 核心闭环

- [ ] 用户能用 Agent 创建循环型和一次性预算卡；
- [ ] 用户可以跳过心愿和数据来源后直接使用；
- [ ] 文字、语音、图片能进入统一 Agent 行动流程；
- [ ] 三类被动来源与账单导入使用统一标准化/去重链路；
- [ ] 一笔消费永远不会同时扣减多张预算卡；
- [ ] 低置信、未纳入和数据缺口在首页可见；
- [ ] 循环卡晚结算时，新消费不会丢失或混入旧周期；
- [ ] 用户检查数据后能完成结算；
- [ ] 结余、越线、钱包和待恢复差额计算正确；
- [ ] 用户能按真实成交金额兑现心愿；
- [ ] 迟到交易与退款能追溯原周期并经确认修正。

### 信任与体验

- [ ] 低风险直接执行后可撤销；
- [ ] 高风险动作执行前展示具体金额影响；
- [ ] 首页明确显示各来源覆盖范围；
- [ ] 用户可跳过、断开和之后补连数据来源；
- [ ] 产品不把心愿钱包描述为真实资金或绝对安全可花额度；
- [ ] Agent 不输出未经规则引擎验证的金额结论。

## 八、待继续确认

- 首页卡片密度、配色、字号与 Agent 面板的视觉外形；
- 提醒敏感度与通知频率；
- iOS/macOS 首发顺序和各地区数据连接器上线顺序；
- 正式商业化范围。
