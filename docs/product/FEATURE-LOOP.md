# FEATURE-LOOP — CheckLine 功能循环

> 本文描述已经确认的产品闭环。主导航与确认页字段以 `docs/design/DESIGN.md` 第 3.1 节为准；卡片密度、配色和字号仍待 M4 真实页面验收。

---

## 一、功能地图

价值主次（2026-10-03 已确认）：每日预算循环提供核心答案「预算还能花多少」；记录与 Agent 让状态跟得上消费；结算与心愿赋予结果持续动力。此主次不改变以下循环、确认门禁或金额计算。

```text
首次引导
  ├─ 创建第一张预算卡
  ├─ 可选添加心愿
  ├─ 可选连接数据来源
  └─ 可选导入近期账单
          ↓
每日预算循环
  数据进入 → 标准化 / 去重 → 归属预算 → 首页状态 → Agent 处理
          ↓
周期结算循环
  到期 → 检查记录与覆盖 → 用户确认 → 结余 / 越线结果
          ↓
心愿循环
  结余进入唯一钱包 → 自由选择心愿 → 确认真实购买 → 扣除实际金额
          ↘
     迟到交易 / 退款 → 追溯原记录 → 用户确认修正
```

## 二、核心对象与关系

### 2.1 预算卡 `Budget`

- 名称与用途；
- 额度与基准币；
- 循环型或一次性；
- 当前周期；
- 归属规则；
- 状态：草稿、进行中、待结算、已归档。

### 2.2 消费 `Expense`

- 金额、原币、实际入账金额、时间、商家和备注；
- 最多一张结算预算卡，也可以暂时未纳入预算；
- 多个语义标签；
- 归属状态：已确认、待确认、未纳入；
- 一个或多个来源证据，用于跨来源去重；
- 可追溯到原周期、原消费或心愿兑现。

### 2.3 预算周期 `BudgetPeriod`

- 每个循环周期有独立的开始、结束和结算状态；
- 一次性预算也使用周期记录，但截止日期可以为空；
- 到期后产生待结算状态；
- 循环卡在旧周期未结算时，用“下周期队列”接住新消费。

### 2.4 结算 `Settlement`

- 对应一张预算卡的一个周期；
- 记录确认后的总支出、结余或越线金额；
- 记录结算时的数据覆盖和用户接受状态；
- 后续迟到交易或退款通过调整记录追溯，不静默改写历史。

### 2.5 心愿钱包与心愿 `WishWallet / Wish`

- 全局只有一个心愿钱包；
- 心愿是清单项目，不拥有独立资金账户；
- 钱包余额和待恢复差额来自同一套可追溯账本；
- 心愿按实际购买确认后才扣除钱包。

### 2.6 关键关系

```text
Budget 1 ── N BudgetPeriod
BudgetPeriod 1 ── N Expense（通过唯一结算归属）
Expense 1 ── N SourceEvidence
Expense N ── N Tag（不参与金额结算）
BudgetPeriod 1 ── 0..N Settlement / Adjustment
WishWallet 1 ── N WalletLedgerEntry
Wish 1 ── 0..N WishRedemption
```

**硬规则**：一笔消费不能同时扣减多张预算卡。多重含义通过标签表达。

## 三、首次使用循环

```text
启动 App
  ↓
Agent 询问：你想管理哪部分支出？
  ↓
用户用文字 / 语音 / 图片表达
  ↓
Agent 整理：名称、额度、周期、币种和必要归属规则
  ↓
用户确认第一张预算卡
  ↓
可选：用户表达一个心愿，Agent 整理后确认
  ↓
可选：连接 Apple Pay / 短信 / 邮箱
  ↓
可选：导入近期账单
  ↓
进入首页
```

规则：

- 心愿和数据来源都可以跳过，不阻塞核心入口。
- 当前周期内的近期交易可以直接归类并计入；更早记录只用于帮助识别。
- 用户之后可在设置页补连数据来源，也可在心愿页或首次结算时补充心愿。

## 四、每日预算循环

### 4.1 首页

```text
顶部处理区
  · 待确认交易
  · 未纳入预算与预算归属覆盖
  · 数据来源覆盖缺口
  · 可能 / 确定的边界风险

预算卡主体
  · 按用户固定顺序展示
  · 已用 / 剩余 / 周期进度
  · 待确认金额单独展示

底部常驻 Agent
  · 语音 / 文字 / 图片入口
```

唤起 Agent 后使用底部任务面板。简单操作原地完成；复杂或高风险操作再进入全屏确认。

### 4.2 主动记录

```text
用户说 / 写 / 发图：“午饭 35 元，记到餐饮”
  ↓
Agent 提取金额、时间、商家、预算卡和标签
  ↓
判断风险与把握
  ├─ 明确 + 低风险 → 直接写入 + 立即撤销
  ├─ 归属不确定 → 展示候选，由用户确认
  └─ 高风险修改 → 先展示影响，再确认执行
  ↓
首页金额与状态更新
```

### 4.3 被动记录与导入

```text
Apple Pay / 银行短信 / 邮件 / 账单导入
  ↓
来源适配
  ↓
交易标准化
  ↓
跨来源去重
  ↓
预算归属与置信判断
  ├─ 高置信 → 进入预算卡
  ├─ 低置信 → 暂计最可能卡 + 待确认
  └─ 无合理匹配 → 未纳入预算
  ↓
更新来源覆盖时间和首页状态
```

去重规则：高度一致的多来源记录自动合并成一笔，保留全部来源证据；无法确定时才让用户处理。

### 4.4 纠正与学习

```text
用户纠正一笔交易
  ↓
Agent 提炼可读规则
  ↓
展示可能受影响的相似历史记录
  ↓
用户选择：只改当前 / 确认批量应用
  ↓
规则用于未来判断
```

不允许静默批量改历史。

---

### 4.5 月度额度编辑

预算卡菜单「编辑预算」→输入金额→预览当前月份与以后每月额度、暂计剩余和确定/可能超支→确认保存。取消/失败保留输入且不写账本；成功同时更新未结算月与后续默认，消费、已结算历史、钱包不变。首页仅在成功后滚动剩余数字。输入、预览、初次加载、切卡与减少动态效果/VoiceOver 都静态。

## 五、边界提醒循环

- 系统同时参考已用金额、周期剩余时间和近期消费速度。
- 有截止日期的预算可以提示“按当前速度可能提前用完”。
- 无截止日期的一次性预算只显示剩余额度，不判断消费速度。
- 待确认金额造成的风险只能标为“可能接近或越线”。
- 已确认记录造成的风险才给出确定反馈。
- 提醒必须说明依据，不能只给黑箱结论。

## 六、循环预算结算

```text
旧周期到期
  ↓
预算卡进入待结算
  ↓
到期后的新消费进入下周期队列
  ↓
用户打开结算页
  · 查看待确认交易
  · 查看各来源覆盖到何时
  · 查看可能缺失的数据
  ↓
用户处理关键项，或明确接受当前数据
  ↓
确认结算
  ├─ 有结余 → 先补待恢复差额，再进入心愿钱包
  └─ 越线 → 先扣钱包，不足部分增加待恢复差额
  ↓
新周期正式开始
  ↓
下周期队列一次归入新周期
```

结算不是强制对账，但也不能绕过明显数据缺口静默完成。

---

## 七、一次性预算结算

### 有截止日期

```text
进行中 → 到期进入待结算
           ├─ 用户正常结算
           ├─ 用户提前结算
           └─ 用户延期
```

### 无截止日期

```text
进行中 → 用户确认事情完成 → 主动结算 → 归档
```

一次性预算结算后不自动续期；用户如需复用，可另行复制或新建。

## 八、心愿循环

### 8.1 钱包变化

```text
预算结余
  ↓
有待恢复差额？
  ├─ 有 → 先补差额，剩余再进钱包
  └─ 无 → 全部进钱包

预算越线
  ↓
先扣心愿钱包
  ↓
钱包不足 → 钱包归零 + 记录全局待恢复差额
```

待恢复差额不是第二个钱包，而是同一钱包账本尚未恢复的负向结果。

以上流程在同一钱包基准币内直接成立。来源币与钱包基准币不同时，先按 `PRODUCT.md` 第 6.5 节在用户确认时换算，再补差额或扣钱包。不得把未换算的不同币种金额直接相加。

### 8.2 心愿兑现

```text
用户选择一个心愿
  ↓
只查看是否具备兑现条件，不提前冻结资金
  ↓
Agent 识别到疑似购买，或用户手动选择“我已购买”
  ↓
用户确认心愿与实际成交金额
  ↓
余额足够？
  ├─ 是 → 只扣心愿钱包，心愿标记完成
  └─ 否 → 不能完整兑现；按普通消费处理或等待余额足够
```

目标价格只作参考，钱包按实际成交金额扣除。

## 九、迟到交易与退款

### 9.1 迟到交易

```text
新导入交易属于已结算旧周期
  ↓
系统定位原周期并重算
  ↓
展示对原结算、钱包和待恢复差额的影响
  ↓
用户确认
  ↓
生成追溯调整记录
```

### 9.2 退款

- 普通预算消费退款：追溯原消费，恢复原周期结余，并调整钱包或待恢复差额。
- 心愿购买退款：金额退回钱包，心愿恢复未完成或由用户确认状态。
- 任何影响已结算金额的退款都不能静默处理。

## 十、Agent 动作门禁

| 风险 | 示例 | 门禁 |
|------|------|------|
| 低 | 明确记一笔、查询剩余 | 可直接执行，提供撤销 |
| 中 | 归属不确定、识别多笔图片记录 | 用户确认结构化结果 |
| 高 | 调额度、改周期、删除、批量修改 | 展示影响后确认 |
| 金额结算级 | 完成结算、追溯旧周期、扣钱包、心愿兑现 | 必须明确确认 |

### 2026-10-01 任务与页面衔接

创建 / 记录任务在同一面板中切换小朵与手动；日期、币种、归属、备注、原始文字和图片保持连续，失败保留并按稳定记录身份重试。新建与记录成功后清理草稿，已提交的附件失败提供续传，不能因重试新增消费。预算页默认表单；卡片进入本期工作区，再进入分组记录、待确认筛选、日历、历史与管理，逐级返回恢复状态。历史使用选定周期的记录、结算快照与追溯差额。导入 / 新纠正仅在隔离演示走来源、处理、核对、影响确认、结果与失败恢复，不参与真实账本循环。

## 十一、当前已确认与待设计

### 已确认

- 核心预算—结算—心愿闭环；
- 一笔消费一张结算预算卡；
- 唯一心愿钱包与待恢复差额；
- Agent 范围与风险确认规则；
- 三类可选被动入口和账单导入；
- 循环/一次性预算的结算衔接；
- 迟到交易与退款追溯；
- 首页状态主体 + 常驻 Agent + 底部任务面板；
- 液面卡夹首页、按需展开图形摘要、四 Tab（首页 / 预算 / 心愿 / 分析）；分析按日期查看消费；
- Agent 面板三态（收起 / 任务面板 / 全屏）与升级条件；
- 结算与心愿兑现确认页必须出现的金额影响字段；
- 唯一心愿钱包基准币、换算时点与汇率来源；
- 目标视口与真实内容核对清单（`DESIGN.md` 第 3.1.6 节）；真实页面跑通属于 M4。
