# FEATURE-LOOP — 预算线当前功能架构循环

> 这是当前版本的产品「心电图」。所有功能、交互和改版都必须能在这张图上找到位置。
> 心愿循环保留为后续版本，不进入当前版本主流程。

---

## 一、当前核心实体

> 「预算钱包」是用户界面里的容器表达；底层实体仍叫 `Budget`。用户看到的是一个个独立预算钱包，产品心智仍是「给自己划一条预算线」。

```
┌────────────────────────────────────────────────────────────┐
│                     Budget（预算）                          │
│  ──────────────────────────────────────                    │
│  · 名称（例：6 月生活 / 京都旅行 / Q3 学习）                 │
│  · 主题模板（旅游 / 月度生活 / 约会 / 装修 / 自定义）          │
│  · 时间周期类型：repeating（重复型）/ oneShot（单次型）       │
│  · 起止时间                                                 │
│  · 总额                                                     │
│  · 分类列表（创建时一次性设好）                              │
│  · 超支策略：warnOnly / strictReview                        │
│  · 状态：active / settling / archived                       │
└────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│                  Expense（一笔消费）                        │
│  ──────────────────────────────────────                    │
│  · 金额 / 时间 / 分类 / 备注                                │
│  · 关联预算集（多对多，平等标签，无主副）                     │
│  · 录入来源：manual（当前版本）                              │
│  · 后续录入来源：widget / ocr / voice / shortcut             │
└────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│                  Settlement（结算）                         │
│  ──────────────────────────────────────                    │
│  · 对应预算                                                 │
│  · 总支出 / 结余                                            │
│  · 关联账确认结果                                           │
│  · 结算时间 / 触发方式                                      │
└────────────────────────────────────────────────────────────┘
```

后续版本再加入 `Wish`、`WishAllocation`、`WishContribution`，不要在当前版本提前把心愿流程接进主线。

**关键关系**：

- `Budget` ↔ `Expense`：多对多。一笔消费可同时归属多个预算，所有预算平等。
- `Budget` → `Settlement`：预算结束后生成结算结果。
- `Expense` 只存一份，多预算计入通过中间关系表达，避免重复消费幻象。

## 三、第二层 · 结算循环（中频）

> 任何预算结束（无论循环 / 单次）都走结算清单。当前版本不做转心愿。

```
              ┌────────────────────┐
              │   预算到期触发        │
              └─────────┬──────────┘
                        │
       ┌────────────────┴────────────────┐
       │                                  │
   重复型预算                          单次型预算
   到期自动提醒                        到期提醒
   可进入结算清单                      用户点击结算
       │                                  │
       └──────────────┬──────────────────┘
                      │
                      ▼
              ┌──────────────────────────┐
              │     结算清单页              │
              │  ─────                     │
              │  本预算总支出  ¥4,400       │
              │  本预算总额    ¥5,000       │
              │  最终结余      ¥600         │
              │                            │
              │  关联账确认（如果有）         │
              │  ① 6/15 ¥80 打车           │
              │     同时归 京都 / 生活       │
              │     [都算] [仅京都] [仅生活] │
              │                            │
              │  [完成结算]                 │
              └────────────┬───────────────┘
                           │
                           ▼
              ┌──────────────────────┐
              │   结算完成反馈          │
              │  · 数字确认            │
              │  · 结余展示            │
              │  · 返回首页 / 查看统计   │
              └────────────┬─────────┘
                           │
              ┌────────────┴────────────┐
              ▼                          ▼
     重复型 → 开下周期             单次型 → 归档
```

**当前边界**：

- 结算展示结余，但不让用户选择「转到心愿」。
- 超出金额只进入结算复盘，不自动扣任何心愿。
- 关联账怎么处理必须由用户确认。

## 六、关联账识别

> 同一笔消费被多个预算共享时，结算阶段需要让用户处理。

**识别规则（结算时触发）**：

```
找出所有：同一 Expense ID，关联到 >= 2 个预算的记录

对于每条关联账：
  在结算清单显示：金额 / 时间 / 分类 / 备注
  让用户选择：
    [都算]      → 多个预算各自独立计入
    [仅算 X]    → 只在 X 预算实际计入，其他预算回滚此笔
    [按比例]    → 后续高级特性，当前版本不做
```

**底层数据约束**：

- 同一 Expense 实体只存一份。
- Budget ↔ Expense 是 many-to-many 关系。
- 结算时记录用户最终确认结果。

### 6.1 预算与消费记录删除

```
从预算详情删除预算
   │
   ▼
首次确认删除预算、分类、结算与当前预算关系
   │
   ├─ 没有共享消费
   │    → 删除预算
   │    → 只属于该预算的消费一并删除
   │
   └─ 存在共享消费
        → 二次列出每笔共享消费及仍关联的其他预算
        → 默认全部不勾选：只移除当前预算归属
        → 逐笔勾选“从所有预算删除”
        → 提供全选，但不默认全选
```

从某个预算管理消费记录时：

- 普通记录可单独或批量删除。
- 共享记录默认只解除当前 BudgetExpenseBinding。
- 只有用户明确选择“从所有预算删除”，才删除 Expense 与它的全部 binding。
- 单独删除普通记录提供约 5 秒撤销；删除预算与批量删除经过明确确认后直接生效。
- 当前 MVP 不建立回收站或软删除状态；未来启动回收站前重新更新产品、设计与 Schema。

## 七、超支处理

```
预算金额超过剩余
   │
   ▼
继续允许记下这笔
   │
   ├─ warnOnly
   │    → 温柔提示「今日预算已用完」
   │    → 不阻断用户继续记录
   │
   └─ strictReview
        → 结算清单高亮超出金额
        → 用户复盘时确认
```

不自动扣心愿，不自动挪用其他预算。

## 十、改这张图的纪律

1. 新增功能时，先在每日 / 结算 / 统计日历 / 设置里找位置。
2. 找不到位置 = 这个功能可能不属于当前版本，先回 `PRODUCT.md` 过滤。
3. 涉及心愿、数据模型、金额分配、隐私和迁移时，必须先对齐再改。
4. 改主流程图时，必须同步检查 `ARCHITECTURE.md` 的数据模型影响。
