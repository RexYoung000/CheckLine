# PRD - 预算线 CheckLine 全盘产品需求

> 本 PRD 是 CheckLine 当前阶段的产品需求主文档。
> 它优先服务两件事：统一产品口径，以及指导 Stitch 生成完整 App UI / 交互动效原型。
> 正式代码实现仍按 `ROADMAP.md` 分阶段推进，本轮不新增数据模型字段。

---

## 一、产品定位

**预算线 CheckLine** 是一个用「预算钱包式容器」帮助用户管理消费边界的预算 App。

用户真正需要的不是复杂记账，而是每天知道：

- 这个预算还能花多少
- 今天花的钱归到哪个预算
- 这个月或这次活动有没有守住界限
- 省下来的钱离心愿还有多远

产品心智是「线」：给自己划一条消费边界，随时检查自己离这条线还有多远。
界面表达可以使用「预算钱包」这种更直观的容器结构，帮助用户理解每个独立预算。

---

## 二、核心原则

1. **品牌叫预算线，界面可用钱包结构。**
   「线」是边界和检查心智，「预算钱包」是用户看得懂的 UI 容器。

2. **每个预算都是独立容器。**
   用户可以左右滑动查看不同预算钱包，每个钱包有自己的周期、总额、分类、记录和结算。

3. **钱的决定权归用户。**
   系统可以给默认值，但不能自动决定钱该归到哪个预算、结余该进哪个心愿。

4. **心愿是情感闭环。**
   预算结余不是冷冰冰的剩余数字，而是让用户看到「离想要的东西更近了」。

5. **统计和日历先完整设计，再分阶段开发。**
   PRD 和 Stitch 原型必须完整覆盖统计与消费日历;正式代码实现可后续排期。

6. **"扣血"仅限内部沟通。**
   用户界面不出现「扣血」。对用户说「记一笔」「已用」「最近记录」「记下这笔」「预算快用完了」。

7. **通知是留存的命脉，不是打扰。**
   通知策略需要覆盖预算快用完、多日未记、结算日到、心愿即将达成、新周期开始五个关键触点。每条通知温柔提醒，不制造焦虑。

8. **无障碍是底线，不是加分项。**
   所有交互满足 VoiceOver 标签、Dynamic Type 自适应、最小 44pt 触控区域、WCAG AA 对比度。海外 App Store 审核不可绕过。

## 三、信息架构

### 3.1 iOS 底部导航

底部使用五个主入口：

| Tab | 作用 |
|-----|------|
| 首页 | 当前预算钱包总览、横滑切换、快速记一笔、心愿轻提示 |
| 预算 | 所有预算钱包列表、预算详情、新建/编辑预算 |
| 心愿 | 心愿列表、心愿详情、心愿达成反馈 |
| 统计 | 月度概览、预算 vs 实际、分类分析、消费记录日历 |
| 我的 | 个人状态、预算设置、通知、外观、订阅/关于 |

「记一笔」不占 Tab，使用首页和关键页面的浮动主操作入口。

### 3.2 macOS 结构

macOS 使用 `NavigationSplitView`：

- 侧栏：首页 / 预算 / 心愿 / 统计 / 我的
- 内容区：选中模块详情
- 速记入口：后续用菜单栏和快捷键承载

## 四、核心模块需求

### 4.1 首页

首页参考旧 Stitch「预算钱包」的结构感，但升级为 CheckLine 品牌。

必须包含：

- 顶部轻量品牌区：日期 / CheckLine / 设置入口，不抢主视觉。
- 预算钱包横滑区：用户左右滑动不同预算钱包。
- 当前钱包主卡：预算名称、周期、还能花、已用比例、分类摘要。
- 下方联动列表：随当前钱包切换，展示分类、最近记录或摘要。
- 心愿轻提示：展示一个最相关心愿的进度，不堆多个按钮。
- 快速记一笔：一个清晰主入口，不和结算、心愿、统计按钮抢焦点。

首页不应该出现大量并列操作按钮。结算、编辑、统计等进入详情或二级页。

### 4.2 预算

预算模块是所有预算钱包的管理区。

必须包含：

- 预算钱包列表
- 预算详情
- 新建预算钱包
- 编辑预算钱包
- 分类预算与记录列表
- 到期结算入口

预算详情重点回答：

- 这条预算边界是什么
- 目前还能花多少
- 哪些分类用得最多
- 最近记录是什么
- 是否需要结算

### 4.3 记一笔

记一笔是日常最高频流程。支持五个录入入口：

| 入口 | 场景 | 实现 | 优先级 |
|------|------|------|--------|
| App 内手动 | 主动打开 App 记录 | 首页 + 号按钮 | MVP |
| Widget 速记 | 锁屏一键进入 | Lock Screen Widget + App Intent | MVP |
| 截图识别 | 截到支付成功页 | Photos + Vision OCR | MVP |
| 语音录入 | 长按按钮说话 | Speech + 端侧 AI 解析 | MVP |
| Shortcuts 自动化 | 收到支付通知自动弹 | App Intents | v1.1 |

**通用流程（所有入口汇入）：**

1. 输入或识别金额
2. 选择归到哪些预算
3. 选择分类
4. 添加备注（可选）
5. 点击「记下这笔」

**交互要求：**

- 默认选中当前预算钱包。
- 多预算选择是平等标签，不做主副层级。
- 记录成功后，当前钱包金额和进度平滑更新。
- 如果金额超过当前剩余，温柔提示「这个预算快用完了」，不阻断用户。
- Widget 速记 ≤ 2 步（锁屏点 → 归类弹窗 → 确认）。
- 截图识别自动填金额，用户只需勾预算 + 确认。
- 语音录入失败时展示友善 fallback，引导手动补填。

### 4.4 心愿

心愿是预算结余的归宿。

必须包含：

- 心愿列表
- 心愿详情
- 新建/编辑心愿
- 结算转入记录
- 手动调整记录
- 心愿达成反馈

心愿达成是产品最高光时刻之一，应有明确动画与分享感。

### 4.5 统计

统计模块先进入完整 PRD 和 Stitch 原型。

必须包含：

- 月度概览：本月已用、预算剩余、离心愿近了多少。
- 预算 vs 实际：参考旧 Stitch 统计页的简洁柱状图表现。
- 分类分析：哪些分类占比高，哪些预算接近边界。
- 消费记录日历：作为统计模块内的核心视图。
- 预算筛选：按全部预算或单个预算钱包查看。

统计不是商业财务分析，不做复杂报表。它只帮助用户理解：钱花在哪里、哪条线快到了、哪里离心愿更近。

### 4.6 消费记录日历

日历不单独占 Tab，放在统计模块内。

第一定位：**消费记录日历**。

必须包含：

- 月视图
- 每天是否有记录的视觉标记
- 选中日期后展示当天记录
- 记录显示所属预算钱包标签
- 可切换「全部预算 / 当前预算」

不作为第一版核心：预算周期排期日历、复杂提醒排程。

### 4.7 我的 / 设置

参考旧 Stitch 设置页的分组列表表现。

必须包含：

- 个人状态卡：预算达标率、连续使用、心愿进度摘要。
- 财务管理：预算设置、记录管理、导出（后续）。
- 通用设置：通知、外观、货币、iCloud 同步。
- 订阅/关于：版本、隐私、付费入口。

设置页保持清晰、安静，不做过度营销。

### 4.8 结算

结算是预算周期结束时的仪式。

必须包含：

- 结算清单
- 关联账确认
- 结余金额
- 心愿分配
- 结算高光

结余分配权归用户。系统可以默认选择创建预算时预设的心愿，但用户必须能改。

### 4.9 超支处理

用户在创建预算时选择超支策略，决定超出预算总额后的行为：

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| `warnOnly`（仅提醒） | 弹温柔提示「今日预算已用完」，不阻断记账，不影响心愿基金 | 日常灵活预算 |
| `deductFromWish`（抵扣心愿） | 超支金额在结算时从默认心愿余额扣回 | 严格预算场景 |

交互要求：

- 超支提示不弹红色警告，不制造焦虑。
- 创建预算时引导用户选择，默认 `warnOnly`。
- 结算清单中展示超支抵扣明细（如果选了 `deductFromWish`）。

### 4.10 Widget

Widget 是 CheckLine 最重要的外部曝光位，让用户不打开 App 也能看到预算状态。

**MVP 必须覆盖：**

| Widget | 尺寸 | 内容 |
|--------|------|------|
| 预算状态 | 中尺寸 | 当前主预算钱包名称、剩余金额、进度条、心愿进度 |
| 速记入口 | 锁屏小尺寸 | 一键进入归类弹窗 |

**交互要求：**

- 点击 Widget 跳转 App 对应页面（状态 → 首页，速记 → 归类弹窗）。
- Widget 数据与 App 内数据实时同步（通过 App Groups + SwiftData）。
- 深色背景与主 App `#000814` 一致。

### 4.11 教程

教程帮助用户理解 CheckLine 独有心智模型，对海外市场尤为重要。

**形式：图文卡片教程。** 精美卡片，每张解释一个核心概念，左右滑动浏览。用户随时可从设置页回顾。

**内容主题（5-6 张卡片）：**

| # | 主题 | 说明 |
|---|------|------|
| 1 | 什么是预算线? | 给自己划一条消费边界，线内自由，线外克制 |
| 2 | 多预算怎么用? | 同时管理「月度生活」「京都旅行」「Q3 学习」多个预算钱包 |
| 3 | 一笔消费归多个预算 | 同一笔 ¥38 打车费，可以同时记在「京都旅行」和「6 月生活」 |
| 4 | 心愿怎么攒? | 预算结束的结余自动转入心愿，省下的钱离目标更近 |
| 5 | 结算是什么? | 每次预算结束都是一次高光时刻，看自己守住了多少 |
| 6 | 在哪里记一笔? | Widget / 截图 / 语音 / 手动，四种方式随时记录 |

**触发时机：**

- 首次引导（建完第一个预算和心愿后）自动弹出教程卡片。
- 设置页提供「教程」入口，用户随时可回顾。
- 空状态页面嵌入对应教程入口（如「还没有心愿」→ 链接到「心愿怎么攒?」卡片）。

**设计要求：**

- 视觉风格与「深空暖金」主题一致。
- 每张卡片：主题插图（线条小助手出镜）+ 标题 + 1-2 句简短说明。
- 底部显示分页点（● ○ ○），支持左右滑动和点击翻页。
- 首张卡片后可跳过，最后一张卡片后「开始使用」按钮回主屏。

### 4.12 通知策略

通知是用户留存的命脉，需要覆盖五个关键触点：

| 场景 | 触发条件 | 通知文案（示例） | 频率控制 |
|------|---------|-----------------|---------|
| 预算快用完 | 剩余 ≤ 30% | 「6 月生活还能花 ¥1,500」 | 剩余每降 10% 提醒一次 |
| 多日未记 | 连续 3 天无记录 | 「有 3 天没记了，今天花了什么?」 | 每 3 天最多一次 |
| 结算日到 | 重复型到期 / 单次型到期前 1 天 | 「6 月生活可以结算了」 | 到期当天 + 前一天 |
| 心愿即将达成 | 心愿进度 ≥ 90% | 「离心愿只差 ¥200 了」 | 每跨越 5% 提醒一次 |
| 新周期开始 | 重复型自动开下周期 | 「7 月生活已开启，总额 ¥5,000」 | 新周期当天 |

**交互要求：**

- 所有通知走本地通知（UserNotifications），不依赖服务端。
- 通知点击跳转 App 对应页面。
- 设置页提供通知开关，用户可按场景分别控制。
- 静音时段默认 22:00-08:00 不推送。
- 文案调性温柔不焦虑，不出现「超支」「扣血」「警告」。

## 五、IP 与视觉表达

IP 方向锁定为：**线条小助手**。

它不是儿童化角色，也不是每屏都出现的吉祥物。它是 CheckLine 的轻量品牌伙伴，负责表达：

- 到线提醒
- 检查点
- 空状态引导
- 结算和心愿达成反馈
- 年轻、轻快、不过度严肃的产品气质

使用原则：

- 不抢预算金额和进度条的主视觉。
- 不替用户做金额判断。
- 只在关键节点出现，日常界面以数据和卡片为主。
- 视觉语言围绕线、节点、检查标记、小表情、轻量动效。

## 六、Stitch 原型范围

Stitch 原型必须覆盖完整 App，不只做首页。

页面清单：

- 首页
- 预算列表
- 预算详情
- 新建/编辑预算钱包
- 记一笔弹窗
- 心愿列表
- 心愿详情
- 统计概览
- 消费记录日历
- 我的/设置
- 结算清单
- 结算高光
- 心愿达成反馈
- 教程卡片（首次引导后弹出）
- 设置 → 教程回顾
- 空状态页面（无预算、无心愿、无记录、无统计数据）

关键动效：

- 钱包横滑切换，下方内容同步变化。
- 记一笔后金额和进度平滑变化。
- 统计图表切换有轻量过渡。
- 消费日历点选日期后展示当天记录。
- 线条小助手出现在空状态、提醒、结算、心愿达成等关键节点。
- 结算和心愿达成保留强仪式感。

## 七、验收标准

- 所有相关文档口径一致，不再只围绕首页。
- PRD 明确包含统计、消费日历、设置、心愿单、教程、通知策略、超支处理。
- 五个录入入口（手动/Widget/截图/语音/Shortcuts）均在 PRD 中有完整描述。
- Stitch 本地交付包能独立指导完整 App 原型生成，包含教程页和空状态。
- 用户可见文案不出现「扣血」。
- 旧预算钱包的简洁结构和 feel 被继承，但品牌升级为 CheckLine / 预算线。
- 本轮不新增正式数据模型字段，不改金额计算规则。
- 关键页面满足 VoiceOver 标签、Dynamic Type、44pt 触控目标底线要求。
