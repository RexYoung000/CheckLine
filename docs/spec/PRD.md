# PRD - 预算线 CheckLine 当前版本产品需求

> 本 PRD 是当前版本的产品需求主文档。
> 当前版本先做预算钱包、记一笔、统计回看、我的/设置和基础结算。
> 心愿功能保留为后续版本，不进入当前原型主线、底部导航或 MVP 验收。

---

## 一、产品定位

**预算线 CheckLine** 是一个用「预算钱包式容器」帮助用户管理消费边界的预算 App。

用户每天最需要知道：

- 当前预算还能花多少
- 今天花的钱归到哪个预算
- 哪些分类快到线了
- 这个月或这次活动最终剩了多少

产品心智是「线」：给自己划一条消费边界，随时检查自己离这条线还有多远。

当前设计主参考为旧 Stitch「预算钱包」项目：

https://stitch.withgoogle.com/projects/11707032164273888537

采用它的浅色卡片、钱包横滑、分组列表、简洁统计和安静设置页。旧项目里的真实头像、真实姓名、AI 智能记账建议和真实账户余额心智不能继承。

---

## 二、当前版本原则

1. **品牌叫预算线，界面可用钱包结构。**
   「线」是边界和检查心智，「预算钱包」是用户看得懂的 UI 容器。

2. **每个预算都是独立容器。**
   用户可以左右滑动查看不同预算钱包，每个钱包有自己的周期、总额、分类、记录和结算。

3. **钱的决定权归用户。**
   系统可以给默认值，但不能自动决定一笔钱归到哪个预算，也不能替用户处理关联账。

4. **心愿后置。**
   心愿是长期情感闭环，但当前版本不做心愿 Tab、心愿详情、心愿达成动画和结算转心愿。

5. **统计和日历服务预算回看。**
   统计页回答「钱花在哪里、哪条线快到了、哪天花了什么」，不做复杂财务报表。

6. **"扣血"仅限内部沟通。**
   用户界面不出现「扣血」。对用户说「记一笔」「已用」「最近记录」「记下这笔」「预算快用完了」。

7. **无障碍是底线。**
   所有交互满足 VoiceOver 标签、Dynamic Type 自适应、最小 44pt 触控区域、WCAG AA 对比度。

## 三、信息架构

### 3.1 iOS 底部导航

当前版本使用四个主入口：

| Tab | 作用 |
|-----|------|
| 首页 | 当前预算钱包总览、横滑切换、快速记一笔 |
| 预算 | 所有预算钱包列表、预算详情、新建/编辑预算 |
| 统计 | 月度概览、预算 vs 实际、分类分析、消费记录日历 |
| 我的 | 个人状态、预算设置、通知、外观、关于 |

「记一笔」不占 Tab，使用首页和关键页面的浮动主操作入口。

心愿不作为当前版本独立 Tab。

### 3.2 macOS 结构

macOS 使用 `NavigationSplitView`：

- 侧栏：首页 / 预算 / 统计 / 我的
- 内容区：选中模块详情
- 速记入口：后续用菜单栏和快捷键承载

## 四、核心模块需求

### 4.1 首页

首页参考旧 Stitch「预算钱包」的结构感，但升级为 CheckLine 品牌。

必须包含：

- 顶部轻量品牌区：日期 / 预算线或 CheckLine / 设置入口，不抢主视觉。
- 预算钱包横滑区：用户左右滑动不同预算钱包。
- 当前钱包主卡：预算名称、周期、还能花、已用比例、分类摘要。
- 下方联动列表：随当前钱包切换，展示分类、最近记录或摘要。
- 快速记一笔：一个清晰主入口，不和结算、统计按钮抢焦点。

首页不应该出现大量并列操作按钮。结算、编辑、统计进入详情或二级页。

### 4.2 预算

预算模块是所有预算钱包的管理区。

必须包含：

- 预算钱包列表
- 预算详情
- 新建预算钱包
- 编辑预算钱包
- 分类预算与记录列表
- 到期结算入口

预算详情重点回答：

- 这条预算边界是什么
- 目前还能花多少
- 哪些分类用得最多
- 最近记录是什么
- 是否需要结算

### 4.3 记一笔

记一笔是日常最高频流程。当前版本先做 App 内手动入口。

| 入口 | 场景 | 当前版本 |
|------|------|----------|
| App 内手动 | 主动打开 App 记录 | MVP |
| Widget 速记 | 锁屏一键进入 | 后续 |
| 截图识别 | 截到支付成功页 | 后续 |
| 语音录入 | 长按按钮说话 | 后续 |
| Shortcuts 自动化 | 收到支付通知自动弹 | 后续 |

通用流程：

1. 输入金额
2. 选择归到哪些预算
3. 选择分类
4. 添加备注（可选）
5. 点击「记下这笔」

交互要求：

- 默认选中当前预算钱包。
- 多预算选择是平等标签，不做主副层级。
- 记录成功后，当前钱包金额和进度平滑更新。
- 如果金额超过当前剩余，温柔提示「这个预算快用完了」，不阻断用户。

### 4.4 统计

统计模块进入当前版本主线。

必须包含：

- 月度概览：本月已用、预算剩余、结余趋势。
- 预算 vs 实际：参考旧 Stitch 统计页的简洁柱状图表现。
- 分类分析：哪些分类占比高，哪些预算接近边界。
- 消费记录日历：作为统计模块内的核心视图。
- 预算筛选：按全部预算或单个预算钱包查看。

统计不是商业财务分析，不做复杂报表。它只帮助用户理解：钱花在哪里、哪条线快到了、哪天花了什么。

### 4.5 消费记录日历

日历不单独占 Tab，放在统计模块内。

第一定位：**消费记录日历**。

必须包含：

- 月视图
- 每天是否有记录的视觉标记
- 选中日期后展示当天记录
- 记录显示所属预算钱包标签
- 可切换「全部预算 / 当前预算」

不作为第一版核心：预算周期排期日历、复杂提醒排程。

### 4.6 我的 / 设置

参考旧 Stitch 设置页的分组列表表现。

必须包含：

- 个人状态卡：预算达标率、连续使用、当前预算摘要。
- 财务管理：预算设置、记录管理、导出（后续）。
- 通用设置：通知、外观、货币、iCloud 同步（后续）。
- 关于：版本、隐私、反馈入口。

设置页保持清晰、安静，不做过度营销。

### 4.7 结算

结算是预算周期结束时的阶段回看。

当前版本必须包含：

- 结算清单
- 关联账确认
- 总支出
- 结余金额
- 结算完成反馈

当前版本不做「转到心愿」和心愿分配。结余只作为结算结果展示。

### 4.8 超支处理

用户在创建预算时选择超支策略，决定超出预算总额后的行为：

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| `warnOnly`（仅提醒） | 弹温柔提示「今日预算已用完」，不阻断记账 | 日常灵活预算 |
| `strictReview`（严格复盘） | 结算清单中高亮超出金额，提醒用户确认 | 严格预算场景 |

交互要求：

- 超支提示不弹红色警告，不制造焦虑。
- 创建预算时引导用户选择，默认 `warnOnly`。
- 不把超支金额自动扣到任何心愿或其他预算。

### 4.9 Widget

Widget 不进当前版本实现。当前版本的 UI 文档可以预留入口，但不把 Widget 作为 MVP 验收项。

后续优先做：

- 当前主预算钱包名称
- 剩余金额
- 进度条
- 点击进入首页或记一笔

### 4.10 教程

教程帮助用户理解 CheckLine 的预算钱包心智。

当前版本教程主题：

| # | 主题 | 说明 |
|---|------|------|
| 1 | 什么是预算线 | 给自己划一条消费边界，线内自由，线外克制 |
| 2 | 多预算怎么用 | 同时管理「月度生活」「京都旅行」「Q3 学习」多个预算钱包 |
| 3 | 一笔消费归多个预算 | 同一笔消费可以同时记在多个预算里 |
| 4 | 什么是结算 | 每次预算结束都能看到自己守住了多少 |
| 5 | 在哪里记一笔 | 当前先用 App 内手动入口，后续扩展 Widget / 截图 / 语音 |

触发时机：

- 首次创建预算后展示。
- 设置页提供「教程」入口。
- 空状态页面嵌入对应教程入口。

## 五、通知策略

当前版本先做文档设计，不强制进入 MVP 实现。

| 场景 | 触发条件 | 通知文案（示例） | 频率控制 |
|------|---------|-----------------|---------|
| 预算快用完 | 剩余 ≤ 30% | 「6 月生活还能花 ¥1,500」 | 剩余每降 10% 提醒一次 |
| 多日未记 | 连续 3 天无记录 | 「有 3 天没记了，今天花了什么？」 | 每 3 天最多一次 |
| 结算日到 | 重复型到期 / 单次型到期前 1 天 | 「6 月生活可以结算了」 | 到期当天 + 前一天 |
| 新周期开始 | 重复型自动开下周期 | 「7 月生活已开启，总额 ¥5,000」 | 新周期当天 |

文案调性温柔不焦虑，不出现「超支」「扣血」「警告」。

## 六、Stitch 原型范围

当前版本原型从历史 14 页收敛为 8 个核心页面：

1. 首页
2. 预算列表
3. 预算详情
4. 新建 / 编辑预算钱包
5. 记一笔弹窗
6. 统计概览
7. 消费记录日历
8. 我的 / 设置

可选补充：

- 结算清单
- 结算完成反馈
- 教程卡片
- 空状态页面（无预算、无记录、无统计数据）

不进入当前原型主线：

- 心愿列表
- 心愿详情
- 心愿达成反馈
- 结算转心愿分配

---

## 七、验收标准

- 所有相关文档口径一致：当前版本不做心愿 Tab、心愿详情、心愿达成、转到心愿。
- 当前设计方向明确参考旧「预算钱包」浅色卡片结构。
- 用户可见文案不出现「扣血」。
- 首页只有一个清晰的「记一笔」主入口，不堆并列大按钮。
- 统计、消费日历、设置被覆盖。
- 本轮不新增正式数据模型字段，不改金额计算规则。
- 关键页面满足 VoiceOver 标签、Dynamic Type、44pt 触控目标底线要求。
