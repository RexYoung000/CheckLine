# USER-JOURNEY — 预算线 CheckLine Day 1-30 用户旅程

> 这份文档定义新用户从下载到稳定使用的 30 天典型旅程。
> 不是营销漏斗，是「装上 App 后这 30 天发生什么」。
> 配套阅读：`PRODUCT.md`（产品宪法）、`docs/spec/PRD.md`（产品需求）、`docs/spec/FEATURE-LOOP.md`（功能循环）。

---

## 一、典型用户画像

> 用具体的人讲故事，不用泛化。

### 主角：小满

- 28 岁，互联网产品运营，月薪 ¥18K
- 想攒钱去京都看樱花（计划 ¥5,000，9 月出行）
- 每月日常开销 ¥4,500 左右，剩下来的钱存活期或乱花
- 用过 1-2 个记账 App，坚持不到 7 天
- 已经在支付宝小荷包里放了 ¥800，但「钱进去就忘了」
- iPhone 15 + MacBook Air，重度 Apple 生态用户

### 她现在的核心问题

「我知道我能存下来钱，但每次到月底就没了。我想知道这个月剩多少能花，省下来的钱真的去攒樱花季的钱。」

## 三、阶段详细旅程

### 阶段 1 · Day 0：发现与下载

| 维度 | 内容 |
|------|------|
| **触点** | App Store / 朋友推荐 / 即刻 / 小红书内容 |
| **用户行动** | 看到「预算线 / CheckLine」，下载 |
| **想法** | 「又一个记账？还是这个不一样？看截图好像还行」 |
| **情绪** | 🤔 半信半疑 |
| **痛点** | 不知道这跟其他记账 App 区别在哪 |
| **机会** | App Store 截图前 3 张必须传达「预算钱包 + 心愿激励 + 结算高光」三件事 |

**关键产出（产品侧）：**
- App Store 详情页第 1 屏：预算钱包横滑卡片
- 第 2 屏：结算高光（最有冲击力）
- 第 3 屏：心愿达成全屏动画

---

### 阶段 2 · Day 1：首次启动

| 维度 | 内容 |
|------|------|
| **触点** | App 首次启动 → 欢迎页 → 引导建预算 → 引导建心愿 → 主屏 → 教程卡片 → 申请通知 |
| **用户行动** | 1. 看欢迎页（一句话定位）<br>2. 选「月度生活」模板，设 ¥5,000，分类预填可改<br>3. 选「重复型」周期、`warnOnly` 超支策略<br>4. 建心愿「京都樱花季」，目标 ¥5,000<br>5. 看 5-6 张教程卡片<br>6. 同意通知权限<br>7. 进主屏看到第一个预算钱包 |
| **想法** | 「教程讲得清楚，我大概懂了；6 月生活 ¥5,000，我试试」 |
| **情绪** | 😊 期待 |
| **痛点** | - 教程如果做不好可能直接关；<br>- 分类预填如果不符合用户实际可能要从头改；<br>- 通知权限可能被拒（拒了后续推送策略全废） |
| **机会** | - 教程卡片必须 5-6 张内讲完；<br>- 模板分类要合中国/海外用户日常；<br>- 通知申请前先做预解释（见 `PERMISSIONS.md` 3.1） |

**👉 Aha 时刻 #1**：当用户看完教程理解「我可以同时跑多个预算钱包，省下来的钱自动转心愿」——这是产品的「卖点」第一次落地。

---

### 阶段 3 · Day 1（晚上）：第一笔

| 维度 | 内容 |
|------|------|
| **触点** | 主屏 → + 号 → 归类弹窗 → 记下这笔 → 预算条减少动效 |
| **用户行动** | 晚饭外卖 ¥38，点 +，输入金额，默认勾选「6 月生活」，分类「伙食」，备注空，记下 |
| **想法** | 「啊确实记下了，进度条在动」「明天再试试 Widget」 |
| **情绪** | 😄 满足 |
| **痛点** | - 如果归类弹窗卡顿超过 200ms，用户对「快」的预期破灭<br>- 第一次找不到 + 号位置 |
| **机会** | + 号位置在主屏右下，固定，永远不被滚动遮挡 |

**👉 Aha 时刻 #2**：预算条肉眼可见地缩短 + 数字平滑变化 + Haptic 轻反馈——这是产品的「视觉卖点」第一次落地。

---

### 阶段 4 · Day 2-3：摸索期

| 维度 | 内容 |
|------|------|
| **触点** | 早中晚至少打开 3 次 / 加 Widget / 试截图录入 |
| **用户行动** | - Day 2 早上加了锁屏 Widget，看到预算钱包剩余 ¥4,962<br>- 中午外卖支付宝截图，试截图录入（如果 OCR 准）<br>- Day 3 试语音录入「打车 38」 |
| **想法** | - 「Widget 还行，我能不打开 App 看到」<br>- 「截图识别居然准，省了好几步」<br>- 「语音也不错，但要长按有点别扭」 |
| **情绪** | 😊 上瘾 / 😕 摩擦（如果 OCR 失败） |
| **痛点** | - 截图识别失败时如果体验差，用户直接放弃这个入口<br>- 语音长按找不到（视觉提示弱） |
| **机会** | - OCR 失败后立刻 fallback 到手动输入，不让用户重来<br>- 语音入口在记一笔弹窗内显示「按住录音」提示 |

---

### 阶段 5 · Day 4-7：第一周回顾

| 维度 | 内容 |
|------|------|
| **触点** | 主屏 + 通知（预算还剩 70% 提醒）+ 统计 Tab 第一次进入 |
| **用户行动** | - 一周记了大约 12-15 笔<br>- 第 7 天打开统计 Tab，看月度概览<br>- 看到「本月已用 ¥1,200，预算剩余 ¥3,800」<br>- 心愿进度条几乎没动（因为还没结算） |
| **想法** | - 「钱比我以为的花得快」<br>- 「咦，心愿怎么还是 ¥0，我不是在省钱吗？」 |
| **情绪** | 🤔 困惑 + 😬 警觉 |
| **痛点** | **🔴 这是产品最危险的窗口**：用户以为在省钱，但心愿没动，可能误解为「这 App 没用」 |
| **机会** | - 统计页强调「预计本月可省 ¥X，结算后转入心愿」<br>- 心愿详情页显示「等待 6 月生活结算后注入」<br>- 推送通知「这周省得不错，月底结算后心愿会动」 |

**👉 Moment of Truth #1**：用户必须在第一周末就理解「**结余 → 结算 → 心愿** 是延后发生的**」**。如果不理解，月末就直接卸载。

---

### 阶段 6 · Day 8-15：习惯建立期

| 维度 | 内容 |
|------|------|
| **触点** | 主屏 + Widget + 偶尔截图录入 + 预算半程通知 |
| **用户行动** | - 记一笔频率稳定到每天 1-2 笔<br>- 第 14 天预算用了一半，App 推送「6 月生活已用一半」<br>- 用户回看消费记录日历，发现某天花得多（朋友聚餐 ¥250） |
| **想法** | - 「记账好像没那么累了」<br>- 「我对自己的消费有数了」 |
| **情绪** | 😊 平稳 |
| **痛点** | - 如果通知频率不对（每天提醒一次）会被关掉<br>- 日历加载慢会影响体验 |
| **机会** | - 通知频率：剩余每降 10% 才提醒一次<br>- 日历首屏渲染 ≤ 50ms（详见 `ARCHITECTURE.md` 第十一节性能预算） |

---

### 阶段 7 · Day 16-22：多预算激活

| 维度 | 内容 |
|------|------|
| **触点** | 朋友约京都旅行 → 想新建「京都旅行」预算钱包 → 触发付费墙（如果是免费版） |
| **用户行动** | - 决定 9 月去京都，想单独跑一个旅行预算 ¥5,000<br>- 点「+ 新建预算」<br>- **触发付费墙：「免费版只能开 1 个预算钱包，订阅后无限」** |
| **想法** | - 「是要订阅了吗？¥12/月还能接受」<br>- 「或者 ¥68 买断更划算」 |
| **情绪** | 😬 决策时刻 |
| **痛点** | - 付费墙文案如果太硬（「升级即可解锁」），用户反感<br>- 价格梯度（¥68 买断 < ¥88 年费）逻辑反常，用户疑惑「为什么买断比订阅便宜？」 |
| **机会** | - 付费墙先讲价值（「无限预算 + 多入口 + 高级 Widget」），再讲价格<br>- 修复定价（参见 PRODUCT.md 第八节，建议买断 ¥198+） |

**👉 Moment of Truth #2**：用户已经建立信任 + 体验完整，这是付费转化最高的时刻。**不要在 Day 1-7 就弹付费墙，那时还没体验到价值。**

---

### 阶段 8 · Day 23-28：心愿进度浮现

| 维度 | 内容 |
|------|------|
| **触点** | 主屏 + 心愿 Tab + 通知（预测本月可省 ¥X） |
| **用户行动** | - 用户偶尔点开心愿 Tab，看到「等待 6 月生活结算后注入约 ¥600」<br>- 心愿进度条预览显示 12%（虽然还没真的注入） |
| **想法** | 「快月底了，到底能省多少？」 |
| **情绪** | 🎯 期待 |
| **痛点** | - 「预计 vs 实际」如果差太多，用户失望<br>- 单次型预算（京都旅行）此时还没到结算日，进度感弱 |
| **机会** | - 心愿详情显示「预计 / 实际」对比，让用户期待<br>- 单次型预算给出「行程结束日 = 结算日」明确预期 |

---

### 阶段 9 · Day 28-30：月度结算高光（产品最高峰）

| 维度 | 内容 |
|------|------|
| **触点** | 通知「6 月生活可以结算了」→ 结算清单 → 关联账确认 → 心愿分配 → 结算高光动画 |
| **用户行动** | - 6/30 23:00 收到通知<br>- 进结算清单，看到总支出 ¥4,400 / 预算总额 ¥5,000<br>- 处理 3 笔关联账确认<br>- 看到结余 ¥600，默认全部转入「京都樱花季」<br>- 点「✨ 结算」<br>- **结算高光动画**：800ms 强动画 + Haptic + 「省下了 ¥600」+「离樱花季更近了」 |
| **想法** | - 「卧槽这个动画」<br>- 「我居然真的省下来 ¥600」<br>- 「樱花季已经 12% 了」 |
| **情绪** | 🎉 兴奋 + 满足 + 想分享 |
| **痛点** | 如果动画不够「值得」，用户失望——这是 30 天里最不能掉链子的瞬间 |
| **机会** | - 结算高光必须做满（参见 DESIGN.md 4.6 CelebrationOverlay）<br>- 分享卡片自动生成，用户可以发朋友圈 / Twitter |

**👉 Aha 时刻 #3 + Moment of Truth #3**：这是产品「情感闭环」的兑现。如果这一刻做好了，用户从这里开始**真正成为长期用户**。

## 六、流失风险窗口

按风险等级排：

| 窗口 | 风险 | 流失原因 | 干预策略 |
|------|------|---------|---------|
| 🔴 Day 1 教程 | 极高 | 教程没讲清核心心智 | 测试 5 个真实用户，迭代教程内容 |
| 🔴 Day 4-7 | 高 | 心愿没动，用户以为没用 | 心愿详情显示「等待结算注入」预期文案 |
| 🟡 Day 8-14 | 中 | 通知频率不对被关掉 | 严格按 PRD 4.12 控制频率 |
| 🟡 Day 16-22 | 中 | 付费墙触发突兀 | 修文案 + 修定价 |
| 🟢 Day 28-30 | 低 | 结算动画不够「值得」 | 必须做满，不能 cut corner |

## 七、验收：30 天后用户应该能说什么

理想画像：

> 「我现在每天打开 1-3 次记一笔，一笔不超过 5 秒。月底结算的动画我截了图发了朋友圈，朋友也来下载了。我的京都樱花季已经攒了 12%，离 9 月还有 3 个月，应该能攒齐。我准备订阅一年版，再开一个京都旅行预算。」

如果用户在 Day 30 还做不到上面这些，回头看是哪个阶段的体验没接住。

## 八、未决问题

- [ ] 海外用户和国内用户的旅程差异？海外可能更重视隐私和无障碍提示；国内可能更重视速度和精致动效。
- [ ] 单次型预算（如京都旅行）的旅程独立画一份还是合并？目前合并写在月度旅程里。
- [ ] 心愿在 Day 0-30 内不会达成（一般 ≥ 3 个月），心愿达成动画的旅程要不要单独画 Month 1-3？
- [ ] 付费墙的触发位置是否要 A/B 测试？目前定在「建第 2 个预算」时。
