> 这是产品的「心电图」。所有功能、所有交互、所有改版都必须能在这张图上找到位置。

## 一、核心实体（三大件）

> 说明：「预算钱包」是用户界面里的容器表达；底层实体仍叫 `Budget`。用户看到的是一个个独立预算钱包，产品心智仍是「给自己划一条预算线」。

```
┌────────────────────────────────────────────────────────────┐
│                     Budget（预算）                          │
│  ──────────────────────────────────────                    │
│  · 名称（例：6 月生活 / 京都旅行 / Q3 学习）                 │
│  · 主题模板（旅游 / 月度生活 / 约会 / 装修 / 自定义）          │
│  · 时间周期类型：repeating（重复型）/ oneShot（单次型）       │
│  · 起止时间                                                 │
│  · 总额                                                    │
│  · 分类列表（创建时一次性设好）                              │
│    ── 伙食 ¥800 / 聚会 ¥400 / 约会 ¥300 ...                │
│  · 超支策略：warnOnly（仅警告）/ deductFromWish（抵扣心愿） │
│  · 默认心愿：用户预设结余转入哪个心愿                        │
│  · 状态：active / settling / archived                       │
└────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│                     Wish（心愿）  独立实体                   │
│  ──────────────────────────────────────                    │
│  · 名称 / 图标 / 主题色                                     │
│  · 目标金额 / 已积累金额                                    │
│  · 创建时间 / 达成时间                                      │
│  · 来源：预算结余转入 / 手动加入                             │
│  · 状态：active / achieved / archived                       │
└────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│                  Expense（一笔消费）                        │
│  ──────────────────────────────────────                    │
│  · 金额 / 时间 / 分类 / 备注                                │
│  · 关联预算集（多对多，平等标签，无主副）                     │
│  · 录入来源：manual / widget / ocr / voice / shortcut       │
│  · 关联账标记：同时属于多个预算时打的同笔标识                  │
└────────────────────────────────────────────────────────────┘
```

**关键关系**：
- `Budget` ↔ `Expense`：多对多。一笔消费可同时归属多个预算（平等关系，无主副）。
- `Budget` → `Wish`：多对一。预算创建时预设默认转入心愿（可空）。
- `Budget` → `WishContribution` → `Wish`：结算时产生入账流水，用户可分配到多个心愿。

## 三、第二层 · 结算循环（中频，每个预算结束触发一次）

> **重点：任何预算结束（无论循环 / 单次）都走这条路径。结算高光不是周期型专属。**

```
              ┌────────────────────┐
              │   预算到期触发        │
              └─────────┬──────────┘
                        │
       ┌────────────────┴────────────────┐
       │                                  │
   重复型预算                          单次型预算
   ┌──────────────────┐              ┌──────────────────┐
   │ 例：6月生活        │              │ 例：京都旅行       │
   │ 6/30 23:59       │              │ 7/15 行程结束     │
   │                  │              │                  │
   │ 自动到期          │              │ 到期通知提醒        │
   │ 自动弹结算清单     │              │ 「可以结算了」       │
   │                  │              │                  │
   │                  │              │ 用户主动点击        │
   │                  │              │ 「结算该预算」       │
   └─────────┬────────┘              └─────────┬────────┘
             │                                  │
             └──────────────┬──────────────────┘
                            │
                            ▼  双轨合流
              ┌──────────────────────────┐
              │     结算清单页              │
              │  ─────                     │
              │  本预算总支出  ¥4,400       │
              │  本预算总额    ¥5,000       │
              │                            │
              │  关联账确认（如果有）         │
              │  ─────                    │
              │  系统识别到 3 笔关联账：       │
              │  ① 6/15 ¥80 打车           │
              │     同时归  京都 / 生活      │
              │     [都算] [仅京都] [仅生活] │
              │  ② 6/18 ¥150 酒店早餐      │
              │     ...                    │
              │                            │
              │  最终结余  ¥600             │
              │                            │
              │  转入心愿（用户分配）         │
              │  ─────                     │
              │  ▣ 京都樱花季  ¥600  ✏️    │  ← 创建预算时预设
              │  □ 富士相机   ¥0    ✏️    │  ← 可勾选 + 改金额
              │  □ 不转入                  │
              │                            │
              │  💡 总和 = ¥600（必须配平）  │
              │                            │
              │  [触发结算高光 ✨]          │
              └────────────┬───────────────┘
                           │
                           ▼
              ┌──────────────────────┐
              │   结算高光仪式          │
              │  ─────                │
              │  · 强动画              │
              │  · 数字骤变            │
              │  · Haptic 反馈         │
              │  · 「省下 ¥600」       │
              │  · 「离樱花季更近」     │
              │  · 分享卡片            │
              └────────────┬─────────┘
                           │
              ┌────────────┴────────────┐
              ▼                          ▼
     重复型 → 自动开下周期         单次型 → 归档
     （延续模板与分类）              （状态置 archived）
```

**为什么单次预算更需要仪式感**
单次预算（旅游 / 婚礼 / 装修 / 课程）通常是用户情感投入最重的一笔。「京都之行省下了 ¥600」的高光时刻，应该比「6月生活省下 ¥200」更隆重。仪式感不能因为「类型不同」打折。

## 七、关联账识别引擎（核心算法）

> 同一笔消费被多个预算共享时，结算阶段需要让用户处理。

**识别规则（结算时触发）**：
```
找出所有：同一 Expense ID，关联到 ≥ 2 个预算的记录

对于每条关联账：
  在结算清单显示：金额 / 时间 / 分类 / 备注
  让用户选择：
    [都算]      → 多个预算各自独立计入（默认行为，结余按各预算独立计算）
    [仅算 X]    → 只在 X 预算实际计入，其他预算回滚此笔
    [按比例]    → v2 高级特性，MVP 不做
```

**底层数据约束**：
- 同一 Expense 实体只存一份（避免「重复消费」幻象）
- Budget ↔ Expense 是 many-to-many 关系（通过中间表 `BudgetExpense`）
- 结算时在 `BudgetExpense` 上写入 `finalAttribution` 字段记录用户决策

## 八、超支处理（创建预算时选）

```
预算超支
   │
   ▼
读取该预算的 overrunStrategy：

策略 A：warnOnly（仅警告）
  → 弹温柔提示「今日预算已用完」
  → 不影响心愿基金
  → 不阻断用户继续记账

策略 B：deductFromWish（超支抵扣心愿）
  → 弹提示「超支 ¥XX，将从默认心愿扣回」
  → 在该预算结算时，从默认心愿余额扣减
  → 用于「严格预算」场景，用户明确选择
```

## 十、通知触点循环（高频，贯穿每日循环）

> 通知不是额外功能，是每日循环的一部分。用户不打开 App，通知就是产品本身。

```
App 不活跃
   │
   ▼
系统检查通知条件
   │
   ├─ 剩余 ≤ 30% ──→ 「6月生活还能花 ¥1,500」
   ├─ 连续 3 天未记 ──→ 「有 3 天没记了，今天花了什么？」
   ├─ 结算日到 ──→ 「6月生活可以结算了」
   ├─ 心愿进度 ≥ 90% ──→ 「离心愿只差 ¥200 了」
   └─ 新周期开始 ──→ 「7月生活已开启」
   │
   ▼
用户点击通知
   │
   ▼
跳转 App 对应页面
   │ 预算提醒 → 首页
   │ 多日未记 → 归类弹窗
   │ 结算 → 结算清单
   │ 心愿 → 心愿详情
   │ 新周期 → 首页
```

**频率规则**：
- 静音时段 22:00-08:00
- 同场景重复间隔 ≥ 24h
- 设置页可按场景分别开关

## 十二、状态机总览

```
Budget 状态：
  draft（创建中）──► active（进行中）──► settling（结算中）──► archived（已归档）
                                                              │
                                                              └► （重复型）→ 自动 active

Expense 状态：
  draft（编辑中）──► committed（已记下）──► settled（已结算确认归属）

Wish 状态：
  active（进行中）──► achieved（已达成）──► archived（已归档）
```

## 十三、改这张图的纪律

1. 新增功能时，先在五层循环（每日 / 结算 / 心愿 / 统计日历 / 设置）里找位置。
2. 找不到位置 = 这个功能可能不属于「预算线」，先回 PRODUCT.md 第 12 节过滤。
3. 改主流程图时，必须同步改 `ARCHITECTURE.md` 的数据模型。
4. 改了图请在 commit message 里写清楚改了哪一层、动了哪条线。
