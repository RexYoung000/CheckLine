## 一、导航模型

```
                    ┌─────────┐
                    │ 主屏     │  ← iOS TabView / macOS SplitView
                    │ (Home)  │
                    └────┬────┘
                         │
        ┌────────┬───────┼───────┬────────┐
        ▼        ▼       ▼       ▼        ▼
    ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐
    │ 预算  │ │ 心愿  │ │ 统计  │ │ 我的  │
    │ 钱包  │ │ 列表  │ │ 日历  │ │ 设置  │
    └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘
       │        │        │        │
       ▼        ▼        ▼        ▼
    预算详情  心愿详情  统计概览  设置页
    · 进度条  · 环形进度· 图表    · 通知
    · 分类列表· 来源明细· 日历    · 外观
    · 记录列表          · 筛选    · 付费
```

**导航决策**：
- iOS：底部 TabView 5 tab — 首页 / 预算 / 心愿 / 统计 / 我的。记一笔是浮层 CTA（+ 按钮）不在 tab 里。
- macOS：侧栏 NavigationSplitView。侧栏 = 预算列表 + 心愿入口 + 设置。内容区 = 选中项的详情。

## 二、页面层级树

```
Level 0 (入口)
  ├── 主屏 Home
  │     └── 首屏内容：预算钱包横滑 + 当前钱包列表 + 心愿轻提示
  │
Level 1 (导航)
  ├── 预算列表 (BudgetList)
  │     └── → 预算详情 (BudgetDetail)
  │           ├── → 流水列表 → 流水详情（编辑/删除）
  │           └── → 预算设置（修改周期/分类/超支策略）
  ├── 心愿列表 (WishList)
  │     └── → 心愿详情 (WishDetail)
  │           ├── → 心愿来源明细
  │           └── → 心愿设置（修改名称/目标/图标）
  ├── 统计 (Insights)
  │     ├── → 月度概览
  │     ├── → 预算 vs 实际
  │     └── → 消费记录日历
  ├── 记一笔 (Capture) — 浮层 CTA 不占层级
  └── 我的/设置 (ProfileSettings)
        ├── → 默认预算模式
        ├── → 通知
        ├── → 主题/外观
        └── → 付费/订阅

Level 2 (模态)
  ├── 归类弹窗 (CaptureSheet)
  ├── 预算创建 (BudgetCreate) — 步骤式
  ├── 心愿创建 (WishCreate)
  ├── 结算清单 (SettlementChecklist)
  ├── 结算高光 (SettlementHighlight) — 全屏覆盖
  └── 心愿达成 (WishAchieved) — 全屏覆盖
```

## 三、搜索/筛选/排序

- **MVP 不做全局搜索** — 预算和心愿数量少时不需要
- **预算详情流水**：按时间倒序，支持按分类筛选
- **结算清单关联账**：按时间排序，分组显示归属关系

## 四、心智模型

用户如何看待这个 App 的空间结构：

```
「我的预算钱包」  ← 多个并存的预算容器
    │
    ├── 6月生活（当前正在用）
    │     ├── 现在剩多少？
    │     ├── 记一笔花的
    │     └── 月底结算 → 心愿基金
    │
    ├── 京都旅行
    │
    └── Q3 学习

「我的心愿们」  ← 预算省下的归宿
    │
    ├── 京都樱花季（65%）
    │
    └── 富士相机（23%）
```

**设计原则**：预算和心愿在空间上是两个独立的「区域」，但在逻辑上通过结算事件连接。导航要体现这种既独立又连接的关系。

统计是第三个观察区域：它不替用户决策，只帮助用户回看消费记录、预算边界和心愿进度。
