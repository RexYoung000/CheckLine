# PERMISSIONS — CheckLine 权限与连接规范

> 权限、系统自动化和外部数据连接都必须“用到才问、拒绝可用、覆盖透明”。具体 API 落地前同时核对 `../compliance/PRIVACY.md`。

## 当前构建基线

当前二进制不申请任何系统权限，也没有真实 Agent、Apple Pay、短信、邮箱或账单连接。下文是新 V1 的目标规范，不代表这些能力已经实现。权限键、Capability 和网络连接只能随对应实现切片加入。

---

## 一、统一原则

1. **不在启动时批量索权。** 用户触发语音、图片或某个数据来源时才说明并申请。
2. **所有数据来源可跳过。** 拒绝权限后，文字 Agent 与本地确定性账本仍可使用。
3. **先说清覆盖，再请求连接。** 不能把 Apple Pay、短信或邮箱连接描述为“所有消费自动同步”。
4. **只取当前任务需要的数据。** 不读取完整照片库、完整邮箱或完整短信历史。
5. **断开后停止新增。** 设置页必须显示状态、覆盖时间、断开方式和重新授权入口。
6. **系统设置是唯一真相。** App 内状态要实时反映系统权限，不伪造“已连接”。

---

## 二、V1 权限与连接清单

| 能力 | 系统权限/连接 | 触发时机 | 拒绝后的降级 |
|------|---------------|----------|----------------|
| 文字 Agent | 无 | 用户打开底部任务面板 | 始终可用 |
| 语音 Agent | 麦克风 + 语音识别 | 用户首次点击语音 | 改用文字或图片 |
| 图片/OCR | 系统照片选择器或相机（若实现） | 用户首次选择图片 | 改用文字或文件导入 |
| 通知 | `UNUserNotificationCenter` | 用户主动开启提醒，或首次体验到预算状态后 | 仅 App 内提示 |
| Apple Pay 交易自动化 | 用户在系统自动化中主动配置 | 引导页或设置“连接 Apple Pay” | Agent/账单导入 |
| 银行短信自动化 | 用户在系统自动化中主动配置匹配规则 | 设置“连接银行短信” | Agent/账单导入 |
| 邮件账单/小票 | 指定规则、OAuth 最小 Scope 或主动转发 | 设置“连接邮箱” | 主动转发或文件导入 |
| 账单文件导入 | 系统文件选择器 | 用户点击“导入近期账单” | 不影响其他入口 |

Apple Pay 和短信不是 App 获得系统全量读取权限。它们依赖用户创建/授权的系统自动化，把匹配事件主动交给 CheckLine。

## 三、语音

### 3.1 申请时机

用户第一次点击 Agent 语音按钮时，先展示用途说明，再依次申请麦克风和语音识别权限。

建议文案：

> **中文**：用语音快速告诉 CheckLine 刚刚发生了什么。录音只用于转成文字，处理后即丢弃。
>
> **English**: Use your voice to tell CheckLine what happened. Audio is used only for transcription and discarded afterward.

### 3.2 Info.plist

```xml
<key>NSMicrophoneUsageDescription</key>
<string>预算线需要麦克风把你的预算指令转成文字。录音处理后即丢弃。</string>

<key>NSSpeechRecognitionUsageDescription</key>
<string>预算线使用语音识别理解记一笔、查询和预算操作。</string>
```

要求：

- 优先使用端侧识别；
- 必须实际检查目标语言和系统版本是否支持端侧；
- 若需要网络处理，先按隐私文档说明数据流，不能继续使用“完全不上传”的文案；
- 任一权限拒绝后，不反复弹窗，改为设置入口和文字 fallback。

## 四、图片与 OCR

优先使用系统 `PhotosPicker` / `PHPickerViewController` 让用户只选择单张或少量图片，避免申请整个照片库读取权限。

建议文案：

> **中文**：选择一张支付截图、小票或商品图，CheckLine 只提取这次任务需要的信息。
>
> **English**: Select a payment screenshot, receipt, or product image. CheckLine extracts only what this task needs.

如实现相机拍摄，再单独申请 `NSCameraUsageDescription`。使用系统选择器不需要为了“以后可能用”提前申请全库权限。

要求：

- 原图提取完成后丢弃；
- 默认设备端 OCR；
- 图片可能包含多笔交易时，先展示结构化结果再写入；
- 心愿商品图和消费截图必须走不同任务语境，避免错误扣款。

## 五、Apple Pay 系统自动化

连接流程：

```text
设置/引导选择“连接 Apple Pay”
→ 解释可覆盖的交易类型和首次配置要求
→ 打开系统自动化配置或安装模板
→ 用户确认由系统把匹配交易交给 CheckLine
→ CheckLine 记录连接状态和最后覆盖时间
```

要求：

- 不宣称能读取完整 Wallet 历史；
- 用户删除或关闭系统自动化后，App 要显示“需要注意”；
- 只接收系统实际提供的金额、商家、时间和卡片线索；
- 不保存完整卡号；卡片识别只保留展示/去重必要的脱敏信息。

具体触发字段必须在目标 iOS 版本真机验证后写入技术实现，不凭假设承诺。

---

## 六、银行短信系统自动化

CheckLine 不直接读取短信数据库。用户需要在系统自动化中配置匹配条件，把符合条件的交易短信内容交给 CheckLine。

要求：

- 明确不同银行模板覆盖不同；
- 只处理用户规则命中的短信；
- 提取金额、商家、时间和必要卡片线索后，丢弃无关全文；
- 商家缺失或模板不确定时进入待确认；
- 连接页显示已支持模板、最后覆盖和可能缺失。

不得申请或声称拥有“读取全部短信”的能力。

---

## 七、邮箱账单与电子小票

优先级：

1. 用户主动转发指定账单/小票；
2. 用户配置指定发件人/主题规则；
3. 如确需 OAuth，只请求最小可用 Scope，不默认读取整个邮箱。

连接前必须说明：

- 会读取哪些邮件；
- 是否经过开发者服务器；
- 临时内容保留多久；
- 如何断开和删除；
- 邮件通常用于补全，不保证实时。

如果技术方案需要邮件中转服务，必须先更新隐私政策和架构，不得沿用“数据不经过自有服务器”的旧口径。

---

## 八、账单文件导入

- 使用系统文件选择器；
- 用户每次主动选择文件；
- 先预览识别范围、日期和重复数量；
- 只把当前周期记录计入预算；更早记录仅用于识别；
- 导入临时文件在处理后删除；
- 无法解析时保留原文件在用户选择的位置，不私自上传。

---

## 九、通知

通知不是 onboarding 强制步骤。更合适的时机是用户已经创建预算、看到一次状态反馈后，在开启具体提醒时请求。

通知类型：

- 预算可能接近边界；
- 预算已确定接近/越线；
- 周期可以结算；
- 数据来源需要注意。

待确认金额引起的通知必须明确写“可能”。通知不展示敏感交易详情或心愿名称，除非用户在设置中明确允许预览。

拒绝后只保留 App 内顶部处理区，不阻塞任何金额流程。

---

## 十、后续 iCloud（首发待确认）

- iCloud 尚未进入已确认首发范围，不提前启用 Capability；
- 若后续确认同步，iCloud 必须可选，不在启动时制造阻塞；
- 未登录或关闭时使用本地 SwiftData；
- 设置页清楚显示“仅本机”或“已使用私有 iCloud 同步”；
- 多设备结算冲突策略在实现前必须完成技术设计，不能只依赖 last-write-wins 处理金额账本；
- 用户切换 Apple ID 时先保护本地数据，不自动合并未知账本。

---

## 十一、权限与数据来源状态页

建议统一放在“设置 → 数据来源与权限”，展示：

```text
Apple Pay       已连接 · 覆盖至今天 14:30
银行短信        需要注意 · 某银行模板无法识别商家
邮箱账单        未连接 · 可跳过
照片            按选择使用
语音与麦克风    已允许
通知            已关闭
iCloud          仅本机
```

每项提供：用途、当前状态、最后覆盖、限制、连接/断开和系统设置入口。

## 十二、上线前检查

- [ ] 首次启动没有批量权限弹窗；
- [ ] 所有连接都可跳过，文字 Agent 可用；
- [ ] 语音、图片、短信、邮件文案与真实数据流一致；
- [ ] Apple Pay/短信自动化已在目标系统真机验证；
- [ ] 邮箱 Scope 和中转服务已完成隐私审查；
- [ ] 断开来源后不再获取新数据；
- [ ] 数据来源覆盖时间可见；
- [ ] 权限拒绝、撤销和重新授权路径均可用；
- [ ] InfoPlist.strings 中英文完整；
- [ ] Privacy Manifest 和 App Store 隐私标签与最终实现一致。
