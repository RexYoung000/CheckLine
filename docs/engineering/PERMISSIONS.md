# PERMISSIONS - CheckLine 权限与系统能力

本文只把已经进入当前里程碑的权限视为实施要求。未来能力保留申请原则和验收门槛，不提前加入 Info.plist、Capability 或启动弹窗。

## 一、当前基线

当前构建和第一轮 MVP 的核心流程不需要系统权限。

| 能力 | 当前状态 | 当前处理 |
|---|---|---|
| 手动记一笔 | MVP | 无权限 |
| 本地 SwiftData | MVP 计划 | 无权限 |
| 通知 | 第二轮 | 不申请 |
| 照片 / OCR | 第二轮 | 不加入 Usage Description |
| 语音识别 | 第二轮 | 不加入 Usage Description |
| 麦克风 | 第二轮 | 不加入 Usage Description |
| Widget / App Groups | 第二轮及以后 | 不创建 Target 或 Capability |
| iCloud / CloudKit | 后续待定 | 不启用 Capability |
| macOS 系统能力 | 第四轮 | 当前无 macOS Target |

App 启动、创建预算、手动记一笔、查看统计和完成结算都不能依赖权限授权。

## 二、通用原则

### 用到才申请

- 只有用户主动触发对应功能时才申请。
- 不在首次启动时批量请求权限。
- 系统弹窗前用一段简短说明解释用途和拒绝后的结果。

### 拒绝仍可使用核心流程

- 所有自动录入能力都必须回退到手动记一笔。
- 权限拒绝不能阻塞预算、消费、统计和结算。
- 设置页只展示已经进入产品且实际可用的权限状态。

### 最小权限

- 只申请完成当前操作所需的最小范围。
- 能用系统 Picker 完成的场景，不申请整个资料库访问。
- 不以“以后可能会用”为理由提前增加 Usage Description。

## 三、第二轮候选权限

本节是实施门槛，不代表当前 App 已具备这些能力。

### 3.1 通知

用途：预算接近边界、结算到期和新周期开始提醒。

进入条件：

- 通知策略、频率和静音规则已在 PRD 确认。
- App 内相同信息已经可查看，不依赖通知完成业务。
- 首次请求发生在用户已经体验预算价值后，而不是冷启动。

拒绝后：App 内功能完全可用，设置页可引导前往系统设置。

文案不得包含心愿提醒，除非第三轮心愿能力已经正式上线。

### 3.2 照片选择与 OCR

用途：用户主动选择一张支付截图，端侧识别金额并填入待确认表单。

优先方案：使用系统 Photos Picker 让用户选择单张图片，在无需资料库权限的情况下完成读取。只有经过验证确实需要资料库访问时，才增加对应 Usage Description。

进入条件：

- Vision 端侧识别流程已验证。
- 原始图片不保存、不上传、不写入 SwiftData。
- 识别结果必须经过用户确认。
- 失败后可无损回退到手动输入。

### 3.3 语音识别与麦克风

用途：用户主动按住语音入口，将一句话转换为待确认的金额、分类和备注。

可能涉及：

- `NSMicrophoneUsageDescription`
- `NSSpeechRecognitionUsageDescription`

进入条件：

- 已验证目标系统与语言下 Speech 的端侧/联网行为。
- 权限文案与真实处理方式一致，不能未经验证宣称完全离线。
- 原始音频不持久化。
- 解析结果必须进入确认表单，不能直接记入预算。

任一权限拒绝后，语音入口回退为手动记一笔。

## 四、后续系统能力

### Widget 与 App Groups

创建 Widget Target 前确认：

- Widget 属于当前路线图阶段。
- 主 App 与 Widget 的数据共享方式已经设计并测试。
- App Group Identifier、签名 Team 和数据容器一致。
- Widget 只读取展示所需数据，不扩大隐私范围。

### iCloud / CloudKit

iCloud 本身通常不弹传统权限窗，但启用 Capability 会改变数据流和隐私承诺。

启用前必须确认：

- CloudKit 容器与生产环境命名。
- 本地数据迁移、冲突和退出 Apple ID 的行为。
- 用户是否有明确的同步开关与状态反馈。
- `PRIVACY.md` 和 App Store Connect 隐私问卷已同步。

当前 App 不检测 iCloud 账户、不显示同步横幅，也不声称跨设备同步。

### macOS

菜单栏、全局快捷键、剪贴板等能力属于第四轮。创建 macOS Target 后单独补充平台权限和降级策略，不在 iOS 文档中提前承诺。

## 五、Info.plist 与本地化

权限进入当前实现时：

- 只加入实际使用的 Usage Description Key。
- 中英文文案同时维护在对应本地化资源中。
- 文案说明用户获得的能力、处理位置和拒绝后的替代路径。
- 删除功能时同步删除不再使用的权限 Key。

当前 `Info.plist` 不应包含照片、语音、麦克风等权限文案。

## 六、验收清单

每加入一项权限都必须验证：

- 首次允许、首次拒绝和系统设置中重新开启。
- 拒绝后核心流程仍可完成。
- 系统弹窗前没有误导或强迫文案。
- Usage Description 与真实数据行为一致。
- 权限关闭或受限状态下没有空白页和崩溃。
- 中英文系统环境均显示正确文案。
- `PRIVACY.md`、App Store Connect 问卷和 Privacy Manifest 已复核。
