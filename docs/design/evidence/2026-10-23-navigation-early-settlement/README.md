# 录入回程、液体与提前结算 · 2026-10-23

对应 Rex 在手机端反馈的录入关闭后底栏消失、液体／气泡缺失、卡库拖回不连贯，以及新增提前结算。保留双 Tab 和小朵的位置；底栏聚拢仍待讨论。未更改服务器或账本 Schema。

## 实现与核对

- **录入回程**：关闭明确收回任务面板标志，保留草稿／对话；不再以任务标志整体隐藏根 TabView 的无障碍树。根导航根据实际路径显隐，移除把页面被遮挡当成进入详情的生命周期标志。预算详情转录入先关闭原抽屉，退出回调再打开同一预算的录入，避免两个呈现者争抢。
- **液体**：详情原卡片默认停用动画，已接回首页同一原生水面／气泡渲染。减少动态效果和暂停状态保留静态水面及少量气泡；满额度卡也有气泡，零剩余不制造液体。实际截图与间隔像素检查覆盖喷涌结束后及拔卡后的持续表现。
- **卡库回程**：固定输入场景与全局触控坐标；弧线中心卡绘制交接到同一张承接卡面，尺寸和位置跟随父层进度回位。周围轻点不返回，明确箭头可以点击，球面中央仍用于双轴浏览。保留卡库节点直至收束结束，避免默认移除淡化的浮影；中心卡交接只切换绘制归属。
- **提前结算**：Rex 确认保留原周期日程。循环卡已开始即可进入「提前结算」，核对日期、记录与钱包影响后明确提交。本期实际截止到当天，下一期仍按原定日期开始，间隔消费不可绑定未来一期；等待卡显示开始日期／下期额度并禁止录入或再结算。已绑定未来日期记录时阻止提前提交，不忽略记录。正常 Agent 结算仍保持原到期门禁。一次性卡沿用既有主动结束能力，另补尚未开始时拒绝结束。

金额仍由 Decimal 领域服务计算；下一期先按原完整周期生成，再写回已结算期实际截止日。预览不写账本，保存失败回滚，陈旧／重复确认拒绝，缺汇率不按零处理。

首页直接录入的最初基线关闭路径没有稳定复现底栏消失；不能声称已复现所有用户路径。排查确实发现根层级标志与呈现归属不安全，并按对应路径修正、回归。真机测试期间还出现原生 TabBar 丢失 SwiftUI identifier，但截图中按钮存在；已改用实际系统 TabBar 与可见标题验证可操作性，不把测试定位失败当作视觉消失。

中间版本曾通过手势返回断言，但原速抽帧发现卡面交接有两张浮影，随后继续修正绘制身份与交接；不能只用终态截图或「测试通过」替代连续动效检查。最初单测的账本比较还修正了加载正规化的夹具快照，未放宽领域断言。

1. 首页「＋」录入：取消两次、保存一笔、打开再关闭小朵，确认预算／心愿／小朵仍可用。再从预算详情「记一笔」进入，关闭后应回到可用首页。
2. 进入首页等待十秒，观察液体持续漂浮；新卡满额度、拔卡和详情也应保留材质。减少动态效果开启后仅静态呈现。
3. 卡库短拖应回弹，向下充分拖动应连续回首页；箭头可点击，箭头周围空白轻点不返回。球面中央上下滑用于浏览，边缘／底部用于回程。
4. 已开始的循环卡详情点「提前结算」，先取消，再核对后提交。结果留在原页；返回首页显示下期开始日，等待期禁止重复使用或结算。
