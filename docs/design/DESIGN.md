# DESIGN — 预算线当前设计规范

> 本文件是当前版本 UI 的唯一实施参考。
> 当前设计主方向回到旧 Stitch「预算钱包」的浅色卡片式结构。
> 历史深色 14 页原型不再作为当前主设计方向。

配套阅读：`PRODUCT.md`、`FEATURE-LOOP.md`、`ROADMAP.md`。

## 一、设计方向

**浅色预算钱包 - Light Budget Wallet**

设计目标：

- 像一个干净、轻量、可信的 iOS 预算工具
- 首页一眼看懂当前预算还能花多少
- 钱包卡片、分组列表、简洁统计和设置分组保持旧「预算钱包」的清晰感
- 不做 AI 感重的深色炫技界面
- 不把产品做成银行账户或真实余额工具

### 1.1 当前参考

当前主参考项目：

https://stitch.withgoogle.com/projects/11707032164273888537

继承：

- 浅灰页面背景
- 白色圆角卡片
- 横滑预算钱包
- 预算列表分组
- 大数字 + 简洁图表
- 设置页分组列表

不能继承：

- 真实用户头像、真实姓名、真实 ID
- 「AI 智能记账建议」
- 真实账户余额、总资产、银行卡口径
- 旧项目品牌文案
- 用户可见「扣血」

### 1.2 当前结构

当前版本不是只改首页，而是覆盖 App 主线：

- 首页：预算钱包横滑总览
- 预算：预算钱包列表 / 详情 / 新建编辑
- 统计：月度概览 / 消费记录日历
- 我的：设置 / 通知 / 关于
- 记一笔：作为浮动主操作，不占 Tab

心愿不作为当前版本独立 Tab，不做心愿详情和达成反馈。

### 1.3 Tracck 参考边界

本项目参考 `/Users/rexyoung/Downloads/Tracck-master` 的实现方式，不复制其品牌风格。

可参考的产品与交互方法：

- 使用原生 SwiftUI 作为导航、表单、滑动操作和系统反馈的交互骨架。
- 用统一的卡片表面、内边距、圆角和低强度阴影建立信息层级。
- 用大数字承载首页最重要的状态，辅助信息主动退后。
- 用选中态、Toast、数字变化、触感和撤销形成连续反馈。
- 列表行保持稳定高度和清晰的左信息 / 右结果结构，便于快速扫描。
- 通过统一颜色、字体和图标资产形成产品识别，而不是依赖默认系统外观。

明确不照搬的内容：

- 荧光绿主品牌、复杂自定义 TabBar 和 Liquid Glass 兼容层。
- 订阅、Widget、账号管理等超出 CheckLine 当前 MVP 的能力。
- 「订单 / 收入 / 结算」等不属于预算线语义的文案和信息模型。

CheckLine 的目标是“安静、可信的浅色预算钱包”：保留原生 iOS 交互语义，以预算线、钱包表面和剩余金额作为自己的视觉识别。

```swift

```

颜色原则：

- 页面以浅灰背景承托白色卡片。
- 蓝色只用于主品牌、主按钮、选中态和关键进度。
- 状态色只辅助表达，不单独承担信息。
- 暗黑模式后续再做完整适配，不用当前深色历史稿反推浅色设计。

### 2.2 排版

| Token | 字号 | 字重 | 用途 |
|-------|------|------|------|
| `display` | 40pt | bold | 预算剩余大数字 |
| `heading1` | 28pt | bold | 页面标题 |
| `heading2` | 22pt | bold | 区块标题 |
| `heading3` | 17pt | semibold | 卡片标题 |
| `body` | 15pt | regular | 正文 |

- 金额数字使用等宽或圆角数字风格，保持对齐。

### 2.7 Apple HIG Layout 检查口径

官方参考：

https://developer.apple.com/design/human-interface-guidelines/layout

定位：

- Apple HIG Layout 是当前原型和后续 SwiftUI 实现的布局底线，不是视觉风格参考。
- 当前视觉方向仍然是浅色预算钱包：浅灰背景、白色卡片、横滑钱包、分组列表、简洁统计、安静设置页。

检查项：

| 项目 | 当前要求 |
|------|----------|
| 安全区域 | 页面顶部、底部导航、浮动记一笔按钮、底部弹窗必须避开系统状态栏、Home Indicator 和设备圆角区域 |
| 页面边距 | iPhone 主屏保持 20pt 左右边距；横滑钱包可向页面边缘延展，但内容本身仍与页面边距对齐 |
| 可读宽度 | iOS 使用单列全宽布局；macOS 后续用居中最大 640pt 内容宽度 |
| 触控区域 | 所有可交互元素最小 44x44pt；chip 视觉可以更小，但实际点击区域必须达标 |
| 底部导航 | 当前版本 4 个 Tab，底部导航必须预留 safe area，不遮挡内容和 Home Indicator |
| 浮动按钮 | 记一笔按钮必须高于底部导航和 safe area，不遮挡列表关键内容 |
| 表单与键盘 | 新建预算、记一笔弹窗在键盘出现时，金额输入和主按钮必须仍可操作 |
| 横竖屏与尺寸 | 原型先按竖屏 iPhone 验证；真实 App 进入 SwiftUI 后再补 iPad / macOS / Dynamic Type 细化 |

要求：

- 默认勾选当前预算。
- 预算标签是平等多选。
- 切换预算或分类时，已经输入的金额和备注必须保留。
- 打开弹窗后优先聚焦金额；键盘出现时金额输入和主按钮仍然可操作。
- 主按钮文案只能是「记下这笔」。
- 不使用「扣血确认」。
- 保存成功后，当前钱包的剩余金额和预算线在 300ms 内连续更新，并提供轻触反馈和可撤销提示。

#### 首页视觉落地规则

- 横滑钱包是首页第一视觉舞台；每张卡必须有独立的白色表面、24pt 左右圆角、轻边框和低强度阴影。
- 当前钱包通过边框、轻微抬升和分页指示表达选中，不依赖颜色单独传达状态。
- 钱包卡内的“还能花”和剩余金额是最高层级；预算名称、周期和分类摘要逐级退后。
- 钱包卡、当前钱包分类和最近记录是同一条工作流，不能使用重复标题或无分组的平铺行打断连续性。
- 分类和最近记录使用独立分组表面；行高、内边距和分隔线保持一致，金额右对齐。
- `记一笔` 使用原生 SwiftUI `Button`，但应有明确的主操作层级，不能只表现为与其他工具按钮无差别的 `+`。
- 记录成功后优先使用不打断上下文的 Toast / 撤销反馈，避免用系统 Alert 抢走用户对预算变化的注意力。
- 带撤销操作的 Toast 默认保留约 5 秒，既不长期遮挡内容，也要给用户足够的反应时间。

#### 当前 SwiftUI 样机落地状态（2026-07-20）

本轮已经落地：

- 预算钱包主卡表面、选中边框、轻阴影和分页指示。
- 剩余金额的大数字层级、数字变化动画和预算线状态色。
- 分类与最近记录的独立分组表面，以及统一的行高、图标容器和金额对齐。
- 底部导航上方的原生胶囊式 `记一笔` 主操作，并通过安全区域为内容预留空间。
- 记录成功、撤销、创建预算和完成结算的非阻断 Toast 反馈。
- 钱包横滑后，主卡、分页、分类、日期和最近记录同步切换。

当前仍是视觉方向样机，不代表最终美术完成。后续页面应复用上述表面、层级和反馈规则，再继续收敛颜色、字体、图标与动效细节。

### 3.9 iOS 体验样机实施范围

当前 HTML 原型同步提供一版原生 SwiftUI 体验样机，用于在 Simulator 和真机验证当前设计方向与主流程手感。

体验样机必须覆盖：

- 原生四 Tab 导航：首页 / 预算 / 统计 / 我的。
- 首页钱包横向分页、当前钱包联动、浮动「记一笔」。
- 预算列表、预算详情、新建预算。
- 记一笔的金额、平等多预算、分类、备注、成功反馈与撤销。
- 按预算查看统计、消费记录日历筛选。
- 进行中预算的只读结算预览、待结算预算的关联账确认与完成反馈。

体验样机使用内存示例数据，不接 SwiftData，不建立正式领域服务，也不作为第一轮 MVP 数据层完成证明。所有用户可见文案仍遵守当前文案与无障碍规范。

### 3.10 原生 iOS 优先阶段

当前阶段不追求最终美术表现，先确认组件性质、系统行为和无障碍语义。体验样机优先直接使用 SwiftUI 默认外观与原生交互：

- App 壳层使用 `TabView`、`NavigationStack`、`Toolbar` 和系统 Sheet。
- 设置、配置、标准数据列表优先使用 `List` / `Form`、`Section` 和 `NavigationLink`。
- 钱包横滑、当前钱包摘要和对应明细属于一个连续交互工作区，必须保持空间连续；使用原生 `ScrollView`、`LazyVStack`、`scrollTargetBehavior` 等布局能力组合，不为追求默认系统外观强行拆成多个 `List Section`。
- 选择与输入使用 `Picker`、`DatePicker`、`Toggle`、`TextField` 和 `Button`，不使用胶囊按钮或自绘网格模拟系统选择器。
- 进度使用 `ProgressView(value:)`；统计图表优先使用 Apple 原生 `Charts` 框架。
- 暂停强化圆角卡片、阴影、浮动按钮、Toast、颜色和自绘日历等视觉包装。它们属于后续视觉阶段，不应阻碍当前原生组件替换。
- 当前页面可以保留最少量的业务展示分组，但不得以品牌样式覆盖系统控件的默认行为、点击反馈、键盘、焦点和 VoiceOver 语义。
- “原生组件优先”不等于“全部使用默认 List 布局”；组件替换不得改变信息架构、交互顺序或内容归属。

## 八、无障碍规范

### 8.1 VoiceOver

| 元素 | 要求 |
|------|------|
| 所有图标按钮 | 必须有 `accessibilityLabel` |
| 金额数字 | 读为完整文本，例如「还能花一千五百二十元」 |
| 进度条 | 提供 `accessibilityValue`，例如「百分之七十」 |
| 装饰性插图 | `accessibilityHidden(true)` |
| 空状态按钮 | 读出操作意图，例如「创建第一个预算」 |

### 8.2 Dynamic Type

| 要求 | 说明 |
|------|------|
| 正文字号 | 必须用语义字号 `.font(.body)` 等 |
| 大数字例外 | display 级别可用固定字号，但要加 `minimumScaleFactor(0.5)` |
| 文本截断 | 按钮、标签、卡片标题不能遮挡或重叠 |

### 8.3 触控目标

| 要求 | 说明 |
|------|------|
| 最小点击区域 | 44x44pt |
| Chip/Pill/分类标签 | 视觉可小于 44pt，tap area 必须撑到 44pt |
| 浮动记一笔按钮 | 至少 56x56pt |

### 8.4 颜色与对比度

| 要求 | 说明 |
|------|------|
| 文字对比度 | WCAG AA：正文 >= 4.5:1，大文字 >= 3:1 |
| 信息不依赖颜色 | 进度条除颜色外要有数字辅助 |
| 状态色 | 接近边界和已用完必须有文案或图标辅助 |
